# pdpa-thai ตรวจจับอะไร และตรวจไม่พบอะไร

**ไทย** · [English](DETECTION.en.md)

เอกสารนี้อธิบายทีละกฎว่ามอด (mod) `pdpa-thai` เวอร์ชัน 0.2.0 มองหาข้อมูลแบบใด เขียนทับอะไรก่อนที่ Claude จะอ่าน และมีข้อจำกัดตรงไหน เนื้อหาเขียนจากโค้ดจริง ได้แก่ [`pdpa-thai/hooks/detect.ts`](../pdpa-thai/hooks/detect.ts) ซึ่งเก็บกฎตรวจจับ และ [`pdpa-thai/hooks/register.tsx`](../pdpa-thai/hooks/register.tsx) ซึ่งเก็บฮุก (hook) ทั้งหมด หากเอกสารนี้กับโค้ดไม่ตรงกัน ให้ถือโค้ดเป็นหลัก และถือว่าเอกสารนี้มีข้อผิดพลาด โปรด[แจ้งใน issue](https://github.com/Boom-Vitt/claude-mods-boombignose/issues/new/choose)

> [!IMPORTANT]
> pdpa-thai เป็นโครงการชุมชนที่ไม่เป็นทางการซึ่งดูแลโดยบุคคลคนเดียว ไม่มีส่วนเกี่ยวข้องกับ Anthropic, สำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล (PDPC), สำนักงานพัฒนาธุรกรรมทางอิเล็กทรอนิกส์ (ETDA), สำนักงานพัฒนารัฐบาลดิจิทัล (DGA), กระทรวงดิจิทัลเพื่อเศรษฐกิจและสังคม (MDES) หรือหน่วยงานรัฐใดของไทย และไม่ได้รับการสนับสนุนหรือการรับรองจากหน่วยงานเหล่านั้น เครื่องมือนี้ออกแบบมาเพื่อช่วยลดปริมาณข้อมูลส่วนบุคคลที่ท่านส่งให้ Claude การใช้เครื่องมือนี้ไม่ได้ทำให้การใช้ Claude ของท่านเป็นไปตาม[พระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562](https://www.pdpc.or.th/wp-content/uploads/2023/12/1_Personal-Data-Protection-2562.pdf) (PDPA) และไม่ได้ทดแทนหน้าที่ใดของท่านตามกฎหมายดังกล่าว เอกสารนี้ไม่ใช่คำแนะนำทางกฎหมาย หากต้องการทราบหน้าที่ของท่าน โปรดปรึกษาทนายความที่มีคุณสมบัติเหมาะสมหรือเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO) ขององค์กร ส่วนการตีความอย่างเป็นทางการ โปรดสอบถาม [PDPC](https://www.pdpc.or.th/) (ถาม-ตอบด้านกฎหมาย: <https://consult.pdpc.or.th/> ตรวจสอบเมื่อ 4 ตุลาคม 2569) เนื้อหาด้านกฎหมายอยู่ใน [PDPA.md](PDPA.md)

## สรุปสั้น

- การตรวจจับใช้กฎแบบ regex (regular expression) ร่วมกับการตรวจสอบบางอย่าง เช่น เลขตรวจสอบ (check digit) ของเลขประจำตัวประชาชน การตรวจแบบ Luhn รหัสนำหน้าเบอร์โทรศัพท์ และเงื่อนไขของโดเมน กฎเหล่านี้**จะตรวจไม่พบ**ข้อมูลส่วนบุคคลบางส่วน และ**จะตรวจจับผิด (false positive)** ข้อความที่ไม่เป็นอันตรายบางส่วน จึงควรถือเป็นเพียงตาข่ายรองรับอีกชั้นหนึ่ง ไม่ใช่หลักประกัน
- การตรวจจับทำงานภายในโปรเซสของ Claude Code (บนเครื่องของท่าน หรือในสภาพแวดล้อมคลาวด์หรือเครื่องระยะไกลที่ท่านใช้รัน Claude Code) มอดไม่เรียกเครือข่าย โปรเซส โมเดล หรือ MCP เอง แต่บทสนทนาที่ปกปิดแล้วยังคงถูกส่งไปยังผู้ให้บริการโมเดลที่ตั้งค่าไว้ (โดยค่าเริ่มต้นคือ Anthropic) เช่นเดียวกับบทสนทนาอื่นของ Claude Code สิ่งที่ไม่ถูกส่งมีเพียงค่าในตำแหน่งที่ตัวป้องกันแทนที่แล้วเท่านั้น หากค่าเดียวกันปรากฏในส่วนที่ตัวป้องกันไม่ได้เขียนทับด้วย (ดู[ข้อจำกัดที่ทราบ](#ข้อจำกัดที่ทราบ)) ค่านั้นจะถูกส่งไป ตัวป้องกันเขียนทับเฉพาะสิ่งที่ Claude Code ส่งให้โมเดล แถวข้อความจึงอาจปรากฏในรูปเดิมบนหน้าจอ ในสตรีมของ SDK หรือผ่าน Remote Control (ซึ่งส่งต่อไปยัง claude.ai หรือแอป Claude) เพียงชั่วครู่ก่อนถูกเขียนทับ และช่องทางอื่น เช่น command hook ในไฟล์ตั้งค่าของท่าน telemetry ขององค์กร และรายงานที่ส่งถึง Anthropic ไม่อยู่ในขอบเขตของตัวป้องกัน
- ในโหมดเริ่มต้น `redact` ค่าที่ตรวจพบจะถูกแทนที่ด้วยป้ายแทนค่า (placeholder) เช่น `[REDACTED:PHONE_1~k3x9q]` ก่อนที่โมเดลจะเห็น

## ขั้นตอนการตรวจข้อความ

1. **ปรับรูปแบบตัวอักษร (normalise)** กฎทั้งหมดทำงานบนสำเนาของข้อความที่มีความยาวเท่ากับต้นฉบับ ในสำเนานั้น เลขไทย (๐–๙) จะถูกแปลงเป็นเลขอารบิก (0–9) ส่วนแท็บและช่องว่างแนวนอนชนิดพิเศษจะถูกแปลงเป็นช่องว่างธรรมดา ได้แก่ no-break space (U+00A0), U+1680, U+2000–U+200A, U+202F, U+205F และ ideographic space (U+3000) เมื่อความยาวเท่ากัน ตำแหน่งที่ตรวจพบจึงชี้กลับไปยังตัวอักษรในต้นฉบับได้ตรงตำแหน่ง และตัวอักษรต้นฉบับนั้นคือสิ่งที่ถูกแทนที่

   สิ่งที่ไม่ได้ปรับรูปแบบ ได้แก่ อักขระความกว้างศูนย์ (zero-width) เช่น U+200B และตัวเลขแบบเต็มความกว้าง (full-width) เช่น ０–９ ค่าที่มีอักขระเหล่านี้แทรกอยู่จะตรวจไม่พบ
2. **จับคู่ตามกฎ** กฎทุกข้อด้านล่างทำงานกับข้อความทั้งหมด ไม่มีการจำกัดขนาด
3. **ข้ามป้ายแทนค่าที่มีอยู่แล้ว** ส่วนที่ตรวจพบซึ่งทับกับข้อความที่อยู่ในรูปป้ายแทนค่าแล้วจะถูกตัดทิ้งทั้งส่วน ดังนั้นในข้อความรูป `ป้ายกำกับ: <ป้ายแทนค่า> ข้อความต่อท้าย` ข้อความที่อยู่หลังป้ายแทนค่าจะไม่ถูกปกปิดด้วย (ดูหัวข้อ [ป้ายแทนค่า](#ป้ายแทนค่า))
4. **รวมช่วงที่ทับกัน** ช่วงที่ตรวจพบซึ่งทับซ้อนกันจะรวมเป็นช่วงเดียว และใช้ชนิดของช่วงที่เริ่มก่อน หากเริ่มที่ตำแหน่งเดียวกัน ช่วงที่ยาวกว่าจะได้ก่อน และหากยาวเท่ากัน กฎที่อยู่ก่อนใน `detect.ts` จะได้ก่อน ตัวอย่างเช่น เบอร์โทรศัพท์ที่เขียนต่อจาก `password:` จะได้ชนิด `PHONE` ไม่ใช่ `SECRET`

### เลขประจำตัวประชาชน (`THAI_ID`)

- **รูปแบบ:** ตัวเลข 13 หลักที่ไม่ติดกับตัวเลขอื่น อนุญาตให้มีช่องว่างหรือขีดหนึ่งตัวตรงรอยต่อของกลุ่มตามปกติ (หลังหลักที่ 1, 5, 10 และ 12)
- **การตรวจสอบ:** เลขตรวจสอบแบบ mod-11 คือนำ 12 หลักแรกคูณด้วย 13, 12, … 2 ตามลำดับแล้วรวมกัน หลักที่ 13 ต้องเท่ากับ (11 − ผลรวม mod 11) mod 10 เลขที่ไม่ผ่านจะไม่ถูกแตะต้อง
- **ผลข้างเคียง:** ตัวเลข 13 หลักใดๆ ราว 1 ใน 10 จะผ่านการตรวจนี้โดยบังเอิญ ตัวเลข 13 หลักอื่น เช่น เวลาแบบมิลลิวินาที (timestamp) หรือเลขคำสั่งซื้อ จึงอาจถูกแทนที่ได้

### บัตรชำระเงิน (`CARD`)

- พิจารณาตัวเลขที่ยาวต่อเนื่อง 13 ถึง 22 หลัก ซึ่งอาจมีช่องว่างหรือขีดหนึ่งตัวคั่นระหว่างหลัก ภายในชุดตัวเลขนั้นจะเลือกช่วงที่ยาวที่สุดซึ่งเริ่มและจบตรงรอยต่อของกลุ่ม (ช่องว่างหรือขีด) มี 13 ถึง 19 หลัก และผ่านการตรวจแบบ Luhn ตัวเลขส่วนเกินที่คั่นจากเลขบัตรด้วยช่องว่างหรือขีดจึงไม่ทำให้เลขบัตรหลุดรอด แต่ตัวเลขที่เขียนติดกับเลขบัตรโดยไม่มีตัวคั่นจะทำให้ตรวจไม่พบ เพราะตัวเลขนั้นถูกตรวจรวมกับเลขบัตรเป็นเลขเดียว ซึ่งโดยทั่วไปไม่ผ่าน Luhn
- **ผลข้างเคียง:** ตัวเลขยาวใดๆ ราว 1 ใน 10 ผ่าน Luhn โดยบังเอิญ เลขรหัสอ้างอิงที่ยาว (numeric ID) จึงอาจถูกแทนที่ได้

### เบอร์โทรศัพท์ (`PHONE`)

- **รูปแบบ:** ขึ้นต้นด้วย `0`, `+66` หรือ `0066` แล้วตามด้วยตัวเลขอีก 8 หรือ 9 หลัก ระหว่างหลักใดๆ อาจมีช่องว่างหรือขีดหนึ่งตัว เลขไทยใช้ได้เพราะผ่านการปรับรูปแบบแล้ว
- **การตรวจสอบ:** เมื่อตัดรหัสนำหน้าออก กฎจะรับ 8 หลักที่ขึ้นต้นด้วย 2–7 (กฎถือเป็นโทรศัพท์พื้นฐาน) หรือ 9 หลักที่ขึ้นต้นด้วย 6, 8 หรือ 9 (กฎถือเป็นโทรศัพท์มือถือ) เลขนำหน้าเหล่านี้เป็นสมมติฐานของกฎเอง ไม่ได้ตรวจเทียบกับแผนเลขหมายของหน่วยงานกำกับ กล่าวคือ เบอร์มือถือ 10 หลักที่ขึ้นต้นด้วย `06`, `08` หรือ `09` และเบอร์พื้นฐาน 9 หลักที่ขึ้นต้นด้วย `02` ถึง `07` รวมถึงเบอร์เดียวกันที่เขียนในรูป `+66`
- **ตรวจไม่พบ:** เบอร์ต่างประเทศ การใส่วงเล็บ เช่น `(02)` การใช้จุดเป็นตัวคั่น `66` ที่ไม่มีเครื่องหมายบวก และรูปแบบ `+66 (0)`
- **ผลข้างเคียง:** ตัวเลข 9 หรือ 10 หลักที่ขึ้นต้นด้วยศูนย์และตรงกับรหัสนำหน้าข้างต้นจะถูกถือเป็นเบอร์โทรศัพท์ทั้งหมด รวมถึงเลขอ้างอิงที่เติมศูนย์ข้างหน้าและเบอร์สายด่วนสาธารณะ

### อีเมล (`EMAIL`)

- ไล่ตรวจออกจากเครื่องหมาย `@` แต่ละตัว ย้อนหลังไม่เกิน 64 ตัวอักษรและไปข้างหน้าไม่เกิน 255 ตัวอักษร เวลาที่ใช้จึงแปรผันตามขนาดข้อความ
- **ส่วนหน้า:** ตัวอักษร ASCII ตัวเลข และ `. _ % + -` **โดเมน:** ส่วนที่เป็น ASCII คั่นด้วยจุด ลงท้ายด้วยตัวอักษรอย่างน้อย 2 ตัว หากท้ายโดเมนเป็นจุดหรือขีดจะถูกตัดออก
- **ละเว้น:** `example.com`, `example.org` และ `example.net` แบบตรงตัวเท่านั้น โดเมนย่อยของชื่อเหล่านี้ และชื่อที่สงวนไว้ เช่น `.test` หรือ `.local` จะไม่ถูกละเว้น
- **ผลข้างเคียง:** ข้อความที่ไม่ใช่ข้อมูลส่วนบุคคลแต่มีรูปแบบเดียวกันก็ถูกแทนที่ด้วย เช่น ที่อยู่รีโมต Git แบบ SSH ที่ขึ้นต้นด้วย `git@` และตามด้วยชื่อโฮสต์ที่มีจุด

### ที่อยู่ IPv4 (`IP`)

- **รูปแบบ:** ตัวเลข 1–3 หลักสี่ชุดคั่นด้วยจุด โดยด้านหน้าต้องไม่เป็นตัวเลข จุด `v` หรือ `V` และด้านหลังต้องไม่เป็นตัวเลขหรือจุด
- **การตรวจสอบ:** ทุกส่วนต้องไม่เกิน 255 และละเว้น `127.x.x.x` (loopback) กับ `0.0.0.0` ส่วนช่วงที่อยู่ภายในเครือข่ายและช่วงที่สงวนไว้สำหรับเอกสาร (เช่น `192.0.2.10`) จะไม่ถูกละเว้น
- **ตรวจไม่พบ:** IPv6 และที่อยู่ IPv4 ที่ตามด้วยจุด (.) ทันที เช่น เมื่ออยู่ท้ายประโยค (จุดนั้นทำให้ไม่ผ่านเงื่อนไข "ด้านหลังต้องไม่เป็นจุด")
- **ผลข้างเคียง:** หมายเลขเวอร์ชันสี่ส่วนที่ไม่มี `v` นำหน้า เช่น `1.0.0.12` จะถูกแทนที่

### ข้อมูลลับ (`SECRET`)

มีกฎ 3 ข้อ

1. **รูปแบบโทเค็นที่รู้จัก:** คีย์ที่ขึ้นต้นด้วย `sk-` ตามด้วยอักขระอย่างน้อย 20 ตัว (เป็นคำนำหน้าที่ผู้ให้บริการ AI หลายรายใช้) โทเค็น GitHub (`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_` ตามด้วยอักขระอย่างน้อย 30 ตัว) AWS access key ID (`AKIA` ตามด้วยอักขระ 16 ตัว) โทเค็น Slack (`xoxb-`, `xoxa-`, `xoxp-`, `xoxr-`, `xoxs-` ตามด้วยอักขระอย่างน้อย 10 ตัว) และข้อความรูปแบบ JWT (สามส่วนคั่นด้วยจุด ส่วนแรกขึ้นต้นด้วย `eyJ`)
2. **โทเค็นแบบ `Bearer`:** คำว่า `Bearer` (ตัวพิมพ์ใหญ่หรือเล็กก็ได้) ตามด้วยโทเค็นยาวอย่างน้อย 20 ตัวอักษร
3. **ค่าที่มีป้ายกำกับ:** ป้ายกำกับ (`password`, `passwd`, `pwd`, `passphrase`, `secret`, `token`, `api_key`, `api-key`, `apikey`, `access_key`, `access-key`, `accesskey` หรือ `รหัสผ่าน` ไม่แยกตัวพิมพ์ใหญ่-เล็ก) ตามด้วย `:` หรือ `=` แล้วตามด้วยค่า ค่าอาจเป็นข้อความในเครื่องหมายคำพูด (เดี่ยวหรือคู่ รองรับอักขระหลีก (escape) และเก็บช่องว่างไว้) หรือข้อความที่ไม่มีเครื่องหมายคำพูดซึ่งยาวไปจนถึงช่องว่าง เครื่องหมายคำพูด จุลภาค หรืออัฒภาค
   - **ละเว้น** เมื่อค่ามีลักษณะเป็นโค้ด ได้แก่ ชื่อชนิดข้อมูล (`string`, `number`, `boolean`, `any`, `unknown`, `undefined`, `null`, `true`, `false`, `void`, `never`, `object`, `str`, `int`, `bool`, `None`, `Optional…`, `Record…`) พาธแบบมีจุดหรือการเรียกฟังก์ชัน (`config.token`, `process.env.API_KEY`, `os.environ["SECRET"]`, `get_token()`) เทมเพลตหรือตัวแปร (`${…}`, `$NAME`, `{{…}}`, `<…>`, `%(…`) หรือค่าที่ซ่อนไว้แล้ว (`*` หนึ่งตัวขึ้นไป หรือ `...`) การตรวจนี้ดูเพียงรูปแบบ รหัสผ่านหรือโทเค็นจริงที่บังเอิญมีรูปแบบเหล่านี้จึงไม่ถูกปกปิดด้วย เช่น คำสองคำที่คั่นด้วยจุด ค่าที่มีเพียง `$` ตามด้วยชื่อ (ตัวอักษร ตัวเลข หรือขีดล่าง เช่น `$NAME`) หรือค่าในวงเล็บมุม
   - ป้ายกำกับไม่ต้องเป็นคำที่แยกเดี่ยว ดังนั้น `client_secret:`, `csrf_token=` และ `PWD=` ก็ตรงกฎด้วย และกฎข้อนี้ไม่รับเครื่องหมายทวิภาคแบบเต็มความกว้าง `：`

ตัวอย่างที่ใช้ค่าปลอมอย่างชัดเจน: `password: not-a-real-one` จะกลายเป็น `password: [REDACTED:SECRET_1~k3x9q]`

กฎชุดนี้ไม่ใช่เครื่องมือสแกนข้อมูลลับ (secret scanner) จะตรวจพบเฉพาะรูปแบบข้างต้นเท่านั้น คีย์ส่วนตัวแบบ PEM (PEM private key) และคีย์ที่ไม่มีป้ายกำกับซึ่งใช้ขีดล่าง เช่น `sk_live_…` จะตรวจไม่พบ และค่าที่มีลักษณะเป็นโค้ดจะถูกข้าม ควรเก็บข้อมูลลับไว้นอกเซสชัน และใช้เครื่องมือสแกนข้อมูลลับโดยเฉพาะ

### ค่าที่มีป้ายกำกับ (`SENSITIVE`, `ADDRESS`, `NAME`)

รูปแบบคือ ป้ายกำกับ เครื่องหมายคำพูด (ถ้ามี) ช่องว่าง (ถ้ามี) แล้วตามด้วย `:` หรือ `：` แบบเต็มความกว้าง หรือ `=` ช่องว่าง (ถ้ามี) เครื่องหมายคำพูด (ถ้ามี) แล้วจึงเป็นค่า ค่าเริ่มที่อักขระตัวแรกที่ไม่ใช่ช่องว่างในบรรทัดเดียวกับป้ายกำกับ (ค่าที่อยู่บรรทัดถัดไปจะไม่ตรงกฎ) และยาวไปจนสุดบรรทัด หรือจนถึงจุลภาค อัฒภาค เครื่องหมายคำพูด หรือ `}` ตัวแรก โดยไม่นับช่องว่างท้ายค่า ค่าที่ขึ้นต้นด้วย `[` หรือ `{` (อาร์เรย์หรืออ็อบเจกต์ของ JSON) จะไม่ตรงกฎเลย จึงไม่มีส่วนใดในค่านั้นถูกแทนที่ เว้นแต่กฎอื่น เช่น `PHONE` หรือ `EMAIL` ตรวจพบ ไม่มีการจำกัดความยาว ป้ายกำกับไม่แยกตัวพิมพ์ใหญ่-เล็กและไม่ต้องเป็นคำที่แยกเดี่ยว

- คำว่า `address` และ `name` ที่อยู่ลำพัง**ไม่ใช่**ป้ายกำกับ โค้ดอย่าง `const address: string` หรือคีย์ `"name"` ใน `package.json` จึงไม่ถูกแตะต้อง
- ป้ายกำกับต้องเขียนตรงตามรายการ `home_address`, `homeAddress`, `political opinions` (รูปพหูพจน์), `ชื่อเล่น` และ `หนังสือเดินทาง` ที่อยู่ลำพังไม่ใช่ป้ายกำกับ และกฎ `DOB` รับเฉพาะ `:`, `：` หรือไม่มีตัวคั่น จึงตรวจไม่พบ `dob=`

- **ผลที่ตามมา:** ที่อยู่ที่เขียนโดยมีจุลภาคหรือเขียนหลายบรรทัดจะถูกแทนที่เพียงบางส่วน ทุกอย่างหลังจุลภาคตัวแรกหรือหลังการขึ้นบรรทัดใหม่จะถูกส่งไปตามที่เขียน และรายการที่เขียนเป็นอาร์เรย์ JSON จะไม่ตรงกฎนี้เลย

### หนังสือเดินทาง เลขบัญชี และวันเกิด

- **`PASSPORT`:** ป้ายกำกับ `passport` (ไม่แยกตัวพิมพ์ใหญ่-เล็ก), `เลขที่หนังสือเดินทาง`, `เลขพาสปอร์ต` หรือ `พาสปอร์ต` ตามด้วยอักขระที่ไม่ใช่ตัวเลขไม่เกิน 20 ตัว แล้วจึงเป็นตัวอักษร 1–2 ตัวและตัวเลข 6–8 หลัก (ตัวอักษรเป็นพิมพ์ใหญ่หรือเล็กก็ได้)
- **`BANK_ACCOUNT`:** ป้ายกำกับ `เลขที่บัญชี`, `หมายเลขบัญชี`, `บัญชี`, `account no`, `account number`, `account #`, `acct`, `พร้อมเพย์` หรือ `promptpay` (ไม่แยกตัวพิมพ์ใหญ่-เล็ก) ตามด้วยอักขระที่ไม่ใช่ตัวเลขไม่เกิน 15 ตัว แล้วจึงเป็นตัวเลข 10 ถึง 15 หลัก ซึ่งอาจมีช่องว่างหรือขีดหนึ่งตัวคั่นระหว่างหลัก เนื่องจากคำว่า `บัญชี` ลำพังก็เป็นป้ายกำกับ ตัวเลข 10 ถึง 15 หลักที่ตามมาไม่ไกลจึงถูกแทนที่ทั้งหมด รวมถึงหมายเลขของบัญชีผู้ใช้ (`บัญชีผู้ใช้`) หากตัวเลขหลังป้ายกำกับยาวเกิน 15 หลัก จะถูกแทนที่เพียง 15 หลักแรก และส่วนที่เหลือจะถูกส่งไปตามที่เขียน
- **`DOB`:** ป้ายกำกับ `วันเกิด`, `date of birth`, `birth date`, `birthdate` หรือ `dob` (ไม่แยกตัวพิมพ์ใหญ่-เล็ก) ตามด้วยทวิภาค (ถ้ามี) แล้วจึงเป็นวันที่ในรูปตัวเลข คือ ตัวเลข 1–4 หลัก 1–2 หลัก และ 1–4 หลัก คั่นด้วย `/`, `.` หรือ `-` ใช้ได้ทั้งปีพุทธศักราชและเลขไทย แต่วันที่ที่เขียนชื่อเดือนเป็นคำจะตรวจไม่พบ

### ชื่อที่มีคำนำหน้า (`NAME`)

- **ภาษาไทย:** `นาย`, `นาง`, `นางสาว`, `น.ส.`, `ด.ช.` หรือ `ด.ญ.` ที่ไม่มีอักษรไทยอยู่ติดด้านหน้า ตามด้วยคำภาษาไทยยาว 2 ถึง 31 ตัวอักษร และอาจตามด้วยคำที่สอง (นามสกุล)
- **ละเว้น:** คำทั่วไปที่บังเอิญขึ้นต้นด้วยคำนำหน้า เช่น นายจ้าง นายกรัฐมนตรี นายกเทศมนตรี นายหน้า นายทะเบียน นายแพทย์ นายตำรวจ นางพยาบาล นางฟ้า และนางงาม รายการทั้งหมดอยู่ใน `NOT_A_NAME` ใน `detect.ts` เนื่องจากการละเว้นดูจากตัวอักษรที่ตามหลังคำนำหน้าทันที ชื่อจริงที่ขึ้นต้นด้วยคำเหล่านี้และเขียนติดกับคำนำหน้า เช่น ชื่อที่ขึ้นต้นด้วย ฟ้า หรือ งาม ต่อจากคำว่า `นาง` จึงตรวจไม่พบด้วย
- **อักษรโรมัน (Latin):** `Mr`, `Mrs`, `Ms`, `Miss` หรือ `Dr` จะมีจุดหรือไม่ก็ได้ ตามด้วยคำหนึ่งหรือสองคำที่ขึ้นต้นด้วยตัวพิมพ์ใหญ่ กฎนี้แยกตัวพิมพ์ใหญ่-เล็กและรับเฉพาะตัวอักษร ASCII
- **ตรวจไม่พบ:** ชื่อที่ไม่มีทั้งคำนำหน้าและป้ายกำกับ ทั้งภาษาไทยและอักษรโรมัน

## ป้ายแทนค่า

ค่าที่ถูกแทนที่จะกลายเป็น `[REDACTED:KIND_n~suffix]` เช่น `[REDACTED:PHONE_1~k3x9q]`

- **ค่าเดียวกันได้ป้ายเดียวกัน** ภายในข้อความชุดเดียวที่ประมวลผลพร้อมกัน ได้แก่ พรอมต์ (prompt) หนึ่งรายการ แถวข้อความ (row) หนึ่งแถวในบทสนทนา ไฟล์แนบหนึ่งรายการ หรือชุดบล็อกบริบท (context block) ที่คำนวณสำหรับบทสนทนาหนึ่ง ค่าเดียวกันจะได้ป้ายเดียวกันเสมอ และค่าใหม่จะได้หมายเลขถัดไปของชนิดนั้น คำว่า "ค่าเดียวกัน" หมายถึงอักขระเหมือนกันหลังการปรับรูปแบบ เลขที่เขียนด้วยเลขไทยกับเลขเดียวกันที่เขียนด้วยเลขอารบิกจึงได้ป้ายเดียวกัน แต่เลขเดียวกันที่เขียนครั้งหนึ่งคั่นด้วยช่องว่างและอีกครั้งคั่นด้วยขีดจะได้สองป้าย
- **ไม่นำหมายเลขกลับมาใช้ซ้ำ** หากข้อความมีป้ายแทนค่าอยู่แล้ว (เช่น ท่านวาง `PHONE_3` กลับเข้ามา) ค่าใหม่ของชนิดนั้นจะได้หมายเลขที่สูงกว่าหมายเลขสูงสุดที่มีอยู่
- **หมายเลขเริ่มใหม่ในแต่ละแถวข้อความ** `PHONE_1` ในข้อความหนึ่งกับ `PHONE_1` ในข้อความถัดไปอาจเป็นคนละค่ากัน และโมเดลไม่สามารถแยกแยะได้
- **ทำซ้ำได้ผลเท่าเดิม (idempotent)** ข้อความที่อยู่ในรูปป้ายแทนค่าแล้วจะไม่ถูกตรวจซ้ำ การปกปิดสองรอบจึงได้ผลเหมือนรอบเดียว ผลข้างเคียงคือ ค่าที่ถูกจงใจห่อไว้ในข้อความที่มีรูปแบบเหมือนป้ายแทนค่าจะไม่ถูกปกปิดเช่นกัน
- **ส่วนต่อท้ายประจำเซสชัน (suffix)** ส่วนหลัง `~` เป็นรหัสสั้นที่ประกอบด้วยอักษรตัวเล็กและตัวเลข (5 ตัว) สร้างจากเวลาของนาฬิกาเมื่อตัวป้องกันต้องใช้ครั้งแรกในเซสชัน และเก็บไว้ในสถานะของมอด รหัสนี้ทำให้ตัวป้องกันรู้ว่าป้ายใดออกโดย*เซสชันนี้* ไฟล์ที่เพียงแสดงรูปแบบของป้าย (เช่น ไฟล์ทดสอบ หรือตัวอย่างรูปแบบในหน้านี้) จึงไม่ถูกปฏิเสธเมื่อ Claude แก้ไข แต่ค่าตัวอย่างอื่นในไฟล์นั้นยังคงถูกปกปิดเมื่อ Claude อ่าน เมื่ออ่านหน้านี้ผ่านตัวป้องกัน ตัวอย่างหลายจุดในหน้านี้จะถูกแทนที่ ให้แก้บรรทัดเหล่านั้นด้วยตนเอง หรือสั่ง `/pdpa-guard off` ระหว่างแก้ไขไฟล์ลักษณะนี้
- **ตรวจการเรียกใช้เครื่องมือ (tool call)** หากข้อมูลที่ส่งเข้าเครื่องมือมีป้ายแทนค่าที่เซสชันนี้ออก การเรียกนั้นจะถูกปฏิเสธ และโมเดลจะได้รับแจ้งให้ขอค่าจริงจากท่าน หรือให้ท่านสั่ง `/pdpa-guard off` การตรวจนี้ช่วยลดโอกาสที่ป้ายแทนค่าจะถูกเขียนลงในไฟล์ คำสั่ง หรือคำขอจริง การตรวจนี้รู้จักเฉพาะส่วนต่อท้ายของเซสชันนี้ ป้ายที่ถูกพิมพ์ใหม่โดยไม่มีส่วนต่อท้าย หรือป้ายที่มีส่วนต่อท้ายของเซสชันอื่น จะไม่ถูกปฏิเสธ หลังเริ่ม Claude Code ใหม่ (รวมถึง `claude --resume`) เซสชันจะได้ส่วนต่อท้ายใหม่ ป้ายแทนค่าที่อยู่ในบทสนทนาที่เปิดต่อจึงไม่ถูกปฏิเสธอีก
- **ย้อนกลับไม่ได้** มอดไม่เก็บตารางจับคู่จากป้ายกลับไปยังค่าเดิม จึงไม่สามารถแปลงป้ายกลับเป็นค่าต้นฉบับได้

## สิ่งที่ถูกเขียนทับ

| ที่มาของข้อความ | ฮุก | `redact` | `block` | `off` |
|---|---|---|---|---|
| พรอมต์ที่ท่านพิมพ์ | `prompt.submit` | แทนที่ค่า | ไม่ส่งพรอมต์ | ไม่เปลี่ยนแปลง |
| แถวข้อความที่บทสนทนาเก็บไว้ ได้แก่ ผลลัพธ์ของเครื่องมือ (tool result) ผลลัพธ์จากฮุก และข้อความอื่นที่ส่งเข้ามาในบทสนทนา | `session.append` | แทนที่ค่า | แทนที่ค่า | ไม่เปลี่ยนแปลง |
| การอ้างไฟล์ด้วย `@file` ไฟล์ที่ถูกแก้ไข ไฟล์ `CLAUDE.md` ในโฟลเดอร์ย่อยที่ถูกอ่านภายหลัง ข้อความเตือน (reminder) และบริบทจากฮุกในไฟล์ตั้งค่า | `prompt.attachment` | แทนที่ค่า | แทนที่ค่า | ไม่เปลี่ยนแปลง |
| บล็อกบริบทของข้อความแรก ได้แก่ `CLAUDE.md` และไฟล์คำสั่งอื่น อีเมลบัญชีของท่าน ข้อมูลโปรเจกต์ และวันที่ | `prompt.context` | แทนที่ค่า | แทนที่ค่า | ไม่เปลี่ยนแปลง |
| การเรียกใช้เครื่องมือที่มีป้ายแทนค่าของเซสชันนี้ | `tool.call` | ปฏิเสธ | ปฏิเสธ | อนุญาต |

ภายในแถวข้อความ จะเขียนทับเฉพาะข้อความ คือบล็อกข้อความธรรมดาและข้อความภายในผลลัพธ์ของเครื่องมือ ส่วนรูปภาพ เอกสาร บล็อกการเรียกใช้เครื่องมือ (`tool_use`) และข้อความคิด (thinking) ของโมเดลจะถูกส่งต่อตามเดิมทั้งหมด คำตอบของโมเดล บทสรุปจากการย่อบทสนทนา (compaction) และข้อความแจ้ง (notice) จะไม่ถูกตรวจ ส่วนการพรางบนหน้าจอ (`/pdpa-blur`) แยกจากกันและไม่ขึ้นกับโหมด (ดูหัวข้อ [`/pdpa-blur` ไม่ใช่ตัวป้องกัน](#pdpa-blur-ไม่ใช่ตัวป้องกัน))

## ข้อจำกัดที่ทราบ

รายการนี้เป็นข้อจำกัดชุดเดียวกับใน [README](../README.md#ข้อจำกัด) และเรียงลำดับเดียวกัน ตามด้วยข้อจำกัดบางข้อที่หน้านี้อธิบายละเอียดกว่า ข้อความตัวเอียงท้ายบางข้ออธิบายผลในทางปฏิบัติ

1. กฎทั้งหมดเป็นนิพจน์ปรกติที่ไม่รับประกันผล **จะมี**ข้อมูลที่ตรวจไม่พบ และ**จะมี**ข้อความทั่วไปบางส่วนถูกปกปิด *อย่าใช้ตัวป้องกันนี้เป็นมาตรการเดียว และหลีกเลี่ยงการใส่ข้อมูลส่วนบุคคลในพรอมต์เท่าที่ทำได้*
2. มอดนี้ไม่ใช่เครื่องมือสแกนความลับ (secret scanner) ตรวจพบเฉพาะรูปแบบโทเค็นและป้ายกำกับที่ระบุไว้ใน [ข้อมูลลับ](#ข้อมูลลับ-secret) และข้ามค่าที่มีลักษณะเป็นโค้ด จึงไม่ควรนำความลับเข้ามาในเซสชัน และควรใช้เครื่องมือสแกนความลับโดยเฉพาะ
3. ค่าหลังป้ายกำกับ (`SENSITIVE`, `ADDRESS`, `NAME`) จะสิ้นสุดที่เครื่องหมายจุลภาค อัฒภาค เครื่องหมายคำพูด `}` หรือการขึ้นบรรทัดใหม่ที่พบก่อน ส่วนที่เหลือของที่อยู่หรือรายการจะถูกส่งไปตามที่เขียน ค่าหลังป้ายกำกับที่ขึ้นต้นด้วย `[` หรือ `{` (อาร์เรย์หรืออ็อบเจกต์ JSON) จะไม่ตรงกับกฎกลุ่มนี้เลย มีเพียงกฎอื่น เช่น `PHONE` หรือ `EMAIL` ที่ยังอาจแทนค่าบางส่วนในนั้นได้
4. ชื่อและที่อยู่ที่ไม่มีป้ายกำกับหรือคำนำหน้าชื่อ เช่น ชื่อที่ปรากฏกลางประโยค จะตรวจไม่พบ *ที่อยู่ที่ไม่มีป้ายกำกับ เช่น `ที่อยู่:` จะถึงโมเดลตามเดิม*
5. ไม่ตรวจเนื้อหาในรูปภาพและเอกสารที่แนบเป็นบล็อกแยก *ภาพสแกนบัตรประชาชน ภาพหน้าจอ หรือไฟล์ PDF จะถึงโมเดลตามเดิม ควรลบข้อมูลเหล่านี้ออกก่อนแชร์ไฟล์*
6. Claude Code ไม่เปิดให้มอดแก้ไขเนื้อหาบางส่วน จึงไม่มีการปกปิดในส่วนนั้น ได้แก่ กระบวนการคิดของโมเดล (thinking) และค่าที่ Claude ส่งให้เครื่องมือ (tool_use input) *หากค่าใดเข้าไปอยู่ในส่วนเหล่านี้แล้ว (เช่น โมเดลพิมพ์ค่าที่อ่านได้จากรูปภาพลงในคำสั่ง) ค่านั้นจะคงอยู่และถูกส่งซ้ำในคำขอถัดๆ ไป*
7. ประวัติการสนทนาที่เปิดต่อ (resume) และทรานสคริปต์ (transcript) ของ subagent ที่บันทึกไว้แล้ว มอดจะไม่ตรวจซ้ำ ส่วนที่ไม่ได้ปกปิดในขณะบันทึกจะถูกส่งไปตามเดิม *รวมถึงประวัติที่บันทึกไว้ขณะปิดตัวป้องกันหรือก่อนติดตั้งมอด*
8. ผลลัพธ์ของเครื่องมือแบบมีโครงสร้างและเนื้อหาของไฟล์แนบ (เช่น ไฟล์ที่อ้างถึงด้วย `@`) ที่ Claude Code เก็บไว้ยังคงเป็นค่าเดิมในทรานสคริปต์ และการแสดงผลลัพธ์ของเครื่องมือบนหน้าจอไม่ถูกพราง *ควรดูแลความปลอดภัยของเครื่องและไฟล์บันทึกบทสนทนาตามปกติ*
9. ประวัติพรอมต์ของ Claude Code เอง (ที่เรียกกลับด้วยปุ่มลูกศรขึ้น) อยู่นอกการควบคุมของมอด และอาจเก็บข้อความที่ผู้ใช้พิมพ์ไว้บนเครื่องโดยไม่ปกปิด
10. ไม่ตรวจพรอมต์ระบบ (system prompt) เช่น ข้อมูลสภาพแวดล้อม คำแนะนำของเซิร์ฟเวอร์ MCP และส่วนที่ปลั๊กอินอื่นเพิ่มเข้าไป รวมถึงคำอธิบายของเครื่องมือและ skill
11. ไม่มีการปกปิดใน 3 ส่วนต่อไปนี้ ได้แก่ คำตอบของ Claude ข้อความสรุปที่ได้จากการบีบอัดบทสนทนา (compaction) และข้อความแจ้งจากระบบ (notice) *หากโมเดลเขียนข้อมูลส่วนบุคคลไว้ในคำตอบ เช่น ข้อมูลที่อ่านได้จากรูปภาพ คำตอบนั้นจะถูกบันทึกและส่งกลับไปในคำขอถัดไปโดยไม่เปลี่ยนแปลง*
12. ค่าที่ถูกแบ่งไว้ในหลายข้อความอาจหลุดการตรวจจับ *เช่น ส่งเบอร์โทรศัพท์ครึ่งหนึ่งในพรอมต์แรกและอีกครึ่งในพรอมต์ถัดไป ทั้งสองส่วนจะผ่านไปได้*
13. หาก hook ของมอดเกิดข้อผิดพลาด (throw) หรือใช้เวลาเกินที่ Claude Code กำหนดต่อ hook หนึ่งตัว Claude Code จะข้าม hook นั้นและส่งข้อความไปตามเดิมโดยไม่ปกปิดและไม่มีการแจ้งเตือน (fail-open) *ชุดทดสอบตรวจว่าข้อความที่จงใจให้ประมวลผลยากยังทำงานเสร็จเร็ว ดูหัวข้อ [ประสิทธิภาพ](#ประสิทธิภาพ)*
14. หากมอดไม่ได้โหลด จะไม่มีการปกปิดใด ๆ และสัญญาณเดียวคือไม่มีรายการ `PDPA:` บนแถบสถานะ ให้ใช้ `claude --debug` เพื่อดูสาเหตุ ทั้งนี้การทำงานแบบ headless (เช่น `claude -p`) ไม่มีแถบสถานะ *หลังสั่งปิดการป้องกัน แถบสถานะจะแสดง `PDPA: off` ดูหัวข้อ [โหมดการทำงานทั้งสาม](#โหมดการทำงานทั้งสาม)*
15. API ของ hook ยังอยู่ในระยะทดลองใช้ (early access) มอดนี้ทดสอบแล้วกับ Claude Code 2.1.289 เท่านั้น เวอร์ชันก่อนหน้าหรือใหม่กว่าอาจข้ามการป้องกันบางส่วนหรือทั้งหมดโดยไม่มีการแจ้งเตือน และป้าย (badge) ของ CI แสดงเพียงว่าชุดทดสอบหน่วย (unit test) ผ่านบน Claude Code เวอร์ชันล่าสุด
16. hook ของปลั๊กอินอื่นที่ทำงานก่อนมอดนี้อาจเห็นข้อความต้นฉบับ
17. ผลลัพธ์ของเครื่องมือและข้อความอื่นในบทสนทนาอาจแสดงในรูปแบบเดิมชั่วครู่ก่อนถูกปกปิด ทั้งบนหน้าจอของผู้ใช้และปลายทางที่เซสชันถูกส่งต่อไปแสดง เช่น Remote Control (ซึ่งส่งต่อผ่านบริการของ Anthropic ไปยัง claude.ai หรือแอป Claude) หรือ SDK stream *หากท่านสตรีมเซสชันไปยังไคลเอนต์ SDK หรือใช้ Remote Control ค่าต้นฉบับอาจไปถึงไคลเอนต์นั้นได้*
18. มอดนี้แก้ไขเฉพาะสิ่งที่ Claude Code ส่งให้โมเดล ช่องทางอื่นเป็นช่องทางแยกต่างหาก ไม่อยู่ในขอบเขตของมอด และอาจได้รับค่าเดิม ได้แก่ Remote Control (ซึ่งส่งต่อผ่านบริการของ Anthropic ไปยัง claude.ai หรือแอป Claude) hook แบบคำสั่ง (command hook) ในการตั้งค่าของผู้ใช้ ระบบรวบรวม telemetry ที่องค์กรตั้งค่าไว้ และรายงานที่ผู้ใช้ส่งให้ Anthropic
19. การพรางบนหน้าจอเป็นเพียงการปิดบังด้วยสี การคัดลอก การเลือกข้อความ โปรแกรมอ่านหน้าจอ การค้นหาใน terminal และการบันทึกหรือ log ของ terminal (เช่น tmux หรือ asciinema) ยังได้ค่าจริง ส่วนวิดีโอบันทึกหน้าจอจะเห็นค่าจริงเมื่อวางเมาส์บนข้อความนั้น terminal ที่ปรับความต่างของสีอัตโนมัติ (เช่น terminal ใน VS Code ซึ่งเปิดการตั้งค่า minimum contrast ratio ไว้โดยค่าเริ่มต้น) อาจแสดงข้อความที่พรางไว้ให้อ่านได้ การพรางใช้ได้เฉพาะ terminal และแอปเดสก์ท็อป และไม่พรางข้อความที่ยาวเกิน 100,000 ตัวอักษร *ดูหัวข้อ [`/pdpa-blur` ไม่ใช่ตัวป้องกัน](#pdpa-blur-ไม่ใช่ตัวป้องกัน)*
20. การปฏิเสธการเรียกเครื่องมือจับเฉพาะป้ายแทนค่าของเซสชันนี้ที่เขียนตรงตามรูปแบบเดิม และไม่ทำงานในโหมด `off` *ป้ายที่พิมพ์ใหม่โดยไม่มีส่วนต่อท้าย หรือป้ายของเซสชันอื่น จะไม่ถูกปฏิเสธ และหลังเริ่ม Claude Code ใหม่หรือสั่ง `claude --resume` เซสชันจะได้ส่วนต่อท้ายใหม่*
21. ข้อความแจ้งเตือนนับเฉพาะรายการที่ตรงกับกฎ การไม่มีข้อความแจ้งเตือนไม่ได้หมายความว่าไม่มีข้อมูลส่วนบุคคลถูกส่งออกไป และการมีข้อความแจ้งเตือนก็ไม่ได้หมายความว่าข้อความนั้นไม่มีข้อมูลส่วนบุคคลเหลืออยู่แล้ว
22. Claude เห็นเพียงป้ายแทนค่า จึงใช้ค่าจริงทำงานไม่ได้ และการปกปิดย้อนกลับไม่ได้ การปิดการป้องกันจึงไม่ได้คืนค่าที่ถูกปกปิดไปแล้ว หากงานต้องใช้ค่าจริง ให้ใช้ `/pdpa-guard off` แล้วส่งค่าจริงอีกครั้ง และเปิดกลับด้วย `/pdpa-guard redact` เมื่องานนั้นเสร็จ ระหว่างที่ปิดอยู่ มอดจะไม่ปฏิเสธการเรียกเครื่องมือที่มีป้ายแทนค่าเดิม จึงควรตรวจสิ่งที่ Claude เขียนลงไฟล์
23. ข้อมูลที่ส่งออกไประหว่างปิดการป้องกัน (`off`) จะคงอยู่ในบทสนทนาตามเดิม การเปิดการป้องกันกลับไม่ได้ปกปิดย้อนหลัง และข้อมูลนั้นจะถูกส่งซ้ำไปกับทุกคำขอถัดไปในบทสนทนาเดียวกัน หากต้องการตัดออก ให้ใช้ `/clear` หรือเริ่มเซสชันใหม่
24. `CLAUDE.md`, context block อื่น และไฟล์แนบ จะคงผลจากครั้งแรกที่ Claude Code เตรียมเนื้อหานั้นไว้ การเปลี่ยนโหมดภายหลังจึงไม่มีผลกับเนื้อหาที่เตรียมไว้แล้ว ทั้งนี้ context block จะถูกเตรียมใหม่หลังใช้ `/clear` หรือหลังการบีบอัดบทสนทนา *บล็อกบริบทถูกเตรียมครั้งเดียวต่อบทสนทนา และไฟล์แนบถูกเตรียมครั้งเดียวต่อโปรเซส ไฟล์แนบจะถูกเตรียมใหม่เมื่อเปิดบทสนทนาต่อ*
25. `CLAUDE.md` และ context block อื่นถูกปกปิดด้วย Claude จึงไม่เห็นค่าจริงที่ผู้ใช้ตั้งใจเขียนไว้ เช่น อีเมลของผู้ใช้ใน `CLAUDE.md` *คำสั่งที่ต้องอาศัยค่านั้นแบบตรงตัว เช่น อีเมลที่ใช้ระบุผู้ร่วมเขียน commit จึงใช้ไม่ได้*
26. ข้อมูลที่เปิดเผยต่อสาธารณะอยู่แล้ว เช่น หมายเลขโทรศัพท์ติดต่อของหน่วยงาน ก็ถูกปกปิดหากตรงกับรูปแบบ
27. มอดนี้ช่วยลดข้อมูลที่ถูกส่งออกไป แต่ไม่ได้ทำให้ Claude Code หยุดส่งบทสนทนา (ที่ปกปิดแล้ว) ไปยังผู้ให้บริการโมเดลที่ตั้งค่าไว้ (โดยค่าเริ่มต้นคือ Anthropic)
28. มอดทำงานแยกตามผู้ใช้และตามเครื่อง และผู้ใช้ปิดได้ทุกเมื่อ (`/pdpa-guard off` หรือ `claude plugin disable`) จึงบังคับใช้จากส่วนกลางไม่ได้ และมอดไม่เก็บบันทึกการตรวจสอบ (audit log) ว่าปกปิดอะไรหรือส่งอะไรออกไป จึงใช้แสดงว่ามีมาตรการควบคุมอยู่จริงไม่ได้

ข้อจำกัดเพิ่มเติมที่เห็นได้จากโค้ด

- **การจัดรูปแบบบางอย่างทำให้ตรวจไม่พบ** ได้แก่ อักขระความกว้างศูนย์ ตัวเลขแบบเต็มความกว้าง จุดหรือวงเล็บภายในตัวเลข ตัวเลขที่เขียนติดกับเลขบัตร และที่อยู่ IPv4 ที่ตามด้วยจุดทันที
- **ข้อความที่ยาวเกิน 100,000 ตัวอักษรจะไม่ถูกพรางบนหน้าจอ** แต่ยังคงถูกตรวจทั้งหมดก่อนส่ง เว้นแต่ฮุกทำงานผิดพลาดหรือใช้เวลาเกินกำหนด (ข้อจำกัดข้อ 13)

## การตรวจจับผิดที่อาจพบ

ในข้อความภาษาไทย

- คำที่ขึ้นต้นด้วยคำนำหน้าและไม่อยู่ในรายการละเว้นจะถูกถือเป็นชื่อ เช่น นางแบบ นางเอก นายทุน และนายพล คำนำหน้า `นางสาว` ที่เขียนลำพัง (เช่น ในรายการคำนำหน้า) ก็ถูกตรวจจับด้วย เพราะอ่านได้เป็น `นาง` ตามด้วยคำหนึ่งคำ
- `ชื่อ:` ตามด้วยอะไรก็ตาม เช่น ชื่อโครงการหรือชื่อสินค้า จะกลายเป็น `NAME` และเนื่องจากป้ายกำกับไม่ต้องเป็นคำแยกเดี่ยว คำที่ลงท้ายด้วย `ชื่อ` แล้วตามด้วยทวิภาค (เช่น `ไม่เชื่อ:`) ก็เข้าเงื่อนไขด้วย
- `บัญชี` ตามด้วยตัวเลข 10 ถึง 15 หลักใดๆ จะกลายเป็น `BANK_ACCOUNT`
- เบอร์โทรศัพท์สาธารณะ และเลขอ้างอิงที่เติมศูนย์ข้างหน้าซึ่งมีรูปแบบเหมือนเบอร์โทรศัพท์ไทย จะกลายเป็น `PHONE`

ในโค้ดและล็อก

- ป้ายกำกับตรงกันได้แม้อยู่ในคำที่ยาวกว่า เช่น `Stack trace:` หรือ `trace =` (มีคำว่า `race`) และ `geopolitical:` (มีคำว่า `political`) จะกลายเป็น `SENSITIVE`
- การระบุชนิดข้อมูลและคีย์ที่มีป้ายกำกับชื่อ เช่น `firstName: string` หรือคีย์ `"lastName"` จะกลายเป็น `NAME` เพราะข้อยกเว้นสำหรับค่าที่เป็นโค้ดใช้กับ `SECRET` เท่านั้น
- `PWD=/some/path`, `token: 512` และคำว่า `secret:` ในประโยค จะกลายเป็น `SECRET`
- เวลาแบบมิลลิวินาที 13 หลักและเลขรหัสอ้างอิงที่ยาว บางครั้งผ่านเลขตรวจสอบของเลขประจำตัวประชาชนหรือการตรวจแบบ Luhn แต่ละการตรวจผ่านโดยบังเอิญราว 1 ใน 10 ตัวเลข 13 หลักลักษณะนี้จึงถูกตรวจจับโดยการตรวจใดการตรวจหนึ่งราว 1 ใน 5
- หมายเลขเวอร์ชันสี่ส่วนที่ไม่มี `v` และที่อยู่ IP ภายในเครือข่าย จะกลายเป็น `IP`
- ที่อยู่รีโมต Git แบบ SSH (`git@` ตามด้วยชื่อโฮสต์ที่มีจุด) และที่อยู่ภายใต้โดเมนย่อยของ `example.com` หรือโดเมน `.test` และ `.local` จะกลายเป็น `EMAIL`
- ชื่อสมมติในข้อมูลตัวอย่าง เช่น `Dr Foo Bar` จะกลายเป็น `NAME`

วิธีรับมือ

- **ปิดตัวป้องกันเฉพาะงานนั้น** สั่ง `/pdpa-guard off` ทำงานให้เสร็จ แล้วสั่ง `/pdpa-guard redact` และพึงระลึกว่าสิ่งที่ส่งไปขณะปิดจะยังคงอยู่ในบทสนทนา
- **ไม่ใส่ค่านั้นในพรอมต์** หากเป็นข้อมูลส่วนบุคคลจริง ให้อธิบายแทนการวางค่า หากเป็นข้อความทั่วไปที่บังเอิญตรงกับป้ายกำกับ ให้เรียบเรียงใหม่ไม่ให้อยู่ในรูป `ป้ายกำกับ: ค่า`
- **รายงานด้วยตัวอย่างที่สร้างขึ้นเอง** เปิด issue พร้อมค่าสมมติที่มีรูปแบบเดียวกัน ห้ามวางข้อมูลส่วนบุคคล โทเค็น หรือเลขประจำตัวจริงลงใน issue

## โหมดการทำงานทั้งสาม

| โหมด | สิ่งที่เกิดขึ้น | ควรใช้เมื่อใด |
|---|---|---|
| `redact` (ค่าเริ่มต้น) | ค่าที่ตรวจพบจะถูกแทนที่ด้วยป้ายแทนค่าก่อนที่โมเดลจะเห็น และการเรียกใช้เครื่องมือที่มีป้ายของเซสชันนี้จะถูกปฏิเสธ | การทำงานประจำวัน โดยเฉพาะเมื่อไฟล์ ล็อก หรือผลลัพธ์ของเครื่องมืออาจมีข้อมูลส่วนบุคคลที่งานนั้นไม่จำเป็นต้องใช้ |
| `block` | พรอมต์ที่พิมพ์และมีข้อมูลที่ตรวจพบจะไม่ถูกส่ง ท่านจะเห็นข้อความแจ้งและแก้ไขเอง ส่วนผลลัพธ์ของเครื่องมือ ไฟล์แนบ และบล็อกบริบทยังคงถูกปกปิด และการตรวจการเรียกใช้เครื่องมือยังทำงาน | เมื่อต้องการแก้พรอมต์ด้วยตนเองแทนการให้ระบบแก้ให้ เช่น ในการสาธิตหรือการอบรม หรือในทีมที่ต้องการสร้างนิสัยไม่วางข้อมูลส่วนบุคคลลงในพรอมต์ |
| `off` | ไม่มีการตรวจหรือแทนที่ใดๆ และไม่ตรวจการเรียกใช้เครื่องมือ ส่วนการพราง (หากเปิดอยู่) ยังทำงาน | เมื่องานต้องใช้ค่าจริง หรือเมื่อการตรวจจับผิดเป็นอุปสรรค และควรเปลี่ยนกลับหลังเสร็จงาน |

สั่ง `/pdpa-guard` โดยไม่ใส่อาร์กิวเมนต์เพื่อดูโหมดปัจจุบัน อาร์กิวเมนต์อื่นนอกจาก `redact`, `block` หรือ `off` จะไม่เปลี่ยนโหมด และแสดงเพียงโหมดปัจจุบัน แถบสถานะจะแสดง `PDPA: <โหมด>` หากไม่มีรายการ `PDPA:` บนแถบสถานะเลย แปลว่ามอดไม่ได้โหลดและไม่มีการปกปิดใดๆ (ดูข้อจำกัดข้อ 14) ข้อความแจ้งสั้นๆ จะบอกจำนวนรายการที่ถูกปกปิดในพรอมต์หรือในแถวข้อความ หรือเหตุผลที่พรอมต์ถูกปฏิเสธ การปกปิดในไฟล์แนบและบล็อกบริบท (เช่น ใน `CLAUDE.md`) จะไม่มีข้อความแจ้ง ข้อความแจ้งนับเฉพาะสิ่งที่กฎตรวจพบ การไม่มีข้อความแจ้งจึงไม่ได้แปลว่าไม่มีข้อมูลส่วนบุคคลถูกส่งออกไป

โหมดและการตั้งค่าการพรางไม่ได้บันทึกลงดิสก์ และจะเริ่มที่โหมด `redact` พร้อมเปิดการพรางทุกครั้งที่เริ่ม Claude Code ส่วน `/clear` จะคงโหมดปัจจุบันไว้หรือไม่นั้น ผู้ดูแลโครงการยังไม่ได้ตรวจสอบ (ดูโหมดปัจจุบันได้โดยใช้ `/pdpa-guard` โดยไม่ระบุอาร์กิวเมนต์ หรือดูที่แถบสถานะ) หากใช้โหมด `block` ต้องตั้งใหม่ทุกครั้งที่เริ่มหรือเปิดบทสนทนาต่อ (resume)

## `/pdpa-blur` ไม่ใช่ตัวป้องกัน

`/pdpa-blur` ใช้เปิดหรือปิดการพรางข้อความบนหน้าจอ การสั่งแต่ละครั้งจะสลับระหว่างเปิดและปิดโดยไม่พิจารณาอาร์กิวเมนต์ใดๆ หากปิดอยู่แล้ว `/pdpa-blur off` จึงจะกลับเป็นเปิด ค่าเริ่มต้นคือเปิด

- ใช้กฎชุดเดียวกับตัวป้องกัน แต่เปลี่ยนเพียงวิธีแสดงข้อความของท่านและของ Claude บนหน้าจอ ไม่เปลี่ยนสิ่งที่ถูกส่งออกไป และทำงานเหมือนกันในทุกโหมด รวมถึง `off`
- ข้อความจริงถูกวาดเป็นสีเทาบนพื้นสีเทา เลย์เอาต์จึงไม่ขยับ เมื่อวางเมาส์บนแถบจะเห็นข้อความ และการเลือกแล้วคัดลอกจะได้ข้อความจริง
- ทำงานเฉพาะบนเทอร์มินัลและแอปเดสก์ท็อป ผลลัพธ์ของเครื่องมือจะไม่ถูกพราง และข้อความที่ยาวเกิน 100,000 ตัวอักษรจะแสดงตามปกติ
- เทอร์มินัลที่ปรับความต่างของสีอัตโนมัติ (เช่น เทอร์มินัลใน VS Code ซึ่งเปิดการตั้งค่า minimum contrast ratio ไว้โดยค่าเริ่มต้น) อาจแสดงข้อความที่พรางไว้ให้อ่านได้ การแชร์หน้าจอหรือวิดีโอบันทึกหน้าจอจะเห็นค่าจริงเมื่อวางเมาส์บนข้อความนั้น และ log ของเทอร์มินัลหรือการบันทึกระดับข้อความ (เช่น tmux หรือ asciinema) ยังเก็บข้อความจริงไว้
- เหมาะสำหรับลดการถูกมองเห็นจากผู้อยู่ใกล้ ไม่ใช่มาตรการความปลอดภัย ก่อนแชร์หน้าจอหรือบันทึกเซสชัน ให้ตรวจในเทอร์มินัลนั้นว่าข้อความที่พรางไว้อ่านไม่ออกจริง หรือไม่ให้ข้อมูลส่วนบุคคลปรากฏบนหน้าจอ

## ประสิทธิภาพ

- กฎเขียนให้เวลาที่ใช้เพิ่มขึ้นตามสัดส่วนของขนาดข้อความ เช่น กฎอีเมลดูย้อนหลังไม่เกิน 64 ตัวอักษรและไปข้างหน้าไม่เกิน 255 ตัวอักษรจาก `@` แต่ละตัว และค่าที่มีป้ายกำกับต้องเริ่มด้วยอักขระที่ไม่ใช่ช่องว่าง ช่องว่างหรือแท็บที่ยาวมากหลังป้ายกำกับจึงถูกข้ามไปในเวลาเชิงเส้น (linear time) การตรวจทำงานกับทุกพรอมต์ ผลลัพธ์ของเครื่องมือ ไฟล์แนบ และบล็อกบริบท และขณะเปิดการพรางจะทำงานทุกครั้งที่วาดข้อความบนหน้าจอด้วย
- ข้อความขนาดใหญ่ถูกตรวจทั้งหมด การปกปิดไม่มีการตัดที่ขนาดใด แต่ฮุกที่ทำงานผิดพลาดหรือใช้เวลาเกินที่ Claude Code กำหนดต่อฮุกยังคงถูกข้าม และข้อความจะถูกส่งไปตามเดิม (ข้อจำกัดข้อ 13) (มีเพียงการพรางบนหน้าจอที่ข้ามข้อความยาวเกิน 100,000 ตัวอักษร)
- ชุดทดสอบมีข้อความขนาดใหญ่เกินปกติที่ต้องยังถูกตรวจ และข้อความที่จงใจให้ประมวลผลยากซึ่งต้องทำงานเสร็จภายในเวลาที่กำหนด ได้แก่ `@` ตัวเลข หรือป้าย `password:` ที่ต่อกันยาวมาก และช่องว่าง แท็บ หรือ no-break space 150,000 ตัวหลังป้ายกำกับ เช่น `dob`, `full name:` และ `ศาสนา:`

## ความเป็นส่วนตัว

- การตรวจจับทำงานภายในโปรเซสของ Claude Code (บนเครื่องของท่าน หรือในสภาพแวดล้อมคลาวด์หรือเครื่องระยะไกลที่ท่านใช้รัน Claude Code)
- `pdpa-thai` และ `context-bar` ไม่เรียกเครือข่าย โปรเซส โมเดล หรือ MCP เอง ส่วน `agents-panel` เริ่มเอเจนต์ย่อย (subagent) ผ่าน `$.agent.spawn` เฉพาะเมื่อท่านกดปุ่ม `▶ run` และเอเจนต์ย่อยนั้นติดต่อผู้ให้บริการโมเดลที่ตั้งค่าไว้ (โดยค่าเริ่มต้นคือ Anthropic) เช่นเดียวกับเอเจนต์ทั่วไป CI ตรวจโค้ดฮุกทุกครั้งที่มีการ push หรือเปิด pull request (ดูหัวข้อ [ตรวจสอบด้วยตนเอง](#ตรวจสอบด้วยตนเอง)) การตรวจเหล่านี้ไม่ใช่การพิสูจน์ โปรดอ่านโค้ดเพื่อยืนยัน
- บทสนทนาที่ปกปิดแล้วยังคงถูกส่งไปยังผู้ให้บริการโมเดลที่ตั้งค่าไว้ (โดยค่าเริ่มต้นคือ Anthropic) เช่นเดียวกับบทสนทนาอื่นของ Claude Code การปกปิดมีผลกับสำเนาที่โมเดลอ่าน ค่าเดิมที่ตัวป้องกันแทนที่แล้วจะไม่อยู่ในสิ่งที่ส่งไปยังโมเดล แต่สำเนาที่ Claude Code เก็บไว้เองไม่ถูกเปลี่ยน (ข้อจำกัดข้อ 8 และ 9) หากค่าเดียวกันปรากฏในส่วนที่ตัวป้องกันไม่เขียนทับ ค่านั้นจะยังถูกส่งไป แถวข้อความอาจไปถึงหน้าจอ ไคลเอนต์ SDK หรือ Remote Control ในรูปเดิมเพียงชั่วครู่ก่อนถูกเขียนทับ (ข้อจำกัดข้อ 17) และช่องทางอื่นไม่อยู่ในขอบเขต (ข้อจำกัดข้อ 18)
- การปกปิดไม่ใช่การทำให้เป็นข้อมูลนิรนาม (anonymisation) ข้อความรอบป้ายแทนค่ายังอาจทำให้ระบุตัวบุคคลได้ทั้งทางตรงหรือทางอ้อม (มาตรา 6 แห่งพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562) บทสนทนาที่ปกปิดแล้วจึงอาจยังเป็นข้อมูลส่วนบุคคล โปรดอ่าน [PDPA.md](PDPA.md)
- เอกสารนี้ไม่ได้อ้างว่าการใช้งานเป็นไปตาม PDPA การใช้บริการ AI ของท่านชอบด้วยกฎหมายหรือไม่ รวมถึงประเด็นการโอนข้อมูลไปต่างประเทศ ขึ้นอยู่กับสถานการณ์ของแต่ละกรณี โปรดอ่าน [PDPA.md](PDPA.md) และปรึกษาทนายความที่มีคุณสมบัติเหมาะสมหรือเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO) ขององค์กร

## ตรวจสอบด้วยตนเอง

ต้องใช้ Claude Code รุ่นที่รองรับปลั๊กอินแบบ hook module โดยมอดชุดนี้ทดสอบกับ Claude Code 2.1.289 เท่านั้น (ดูข้อจำกัดข้อ 15)

1. **อ่านโค้ด** [`detect.ts`](../pdpa-thai/hooks/detect.ts) ยาวไม่ถึง 300 บรรทัด และกฎทุกข้ออยู่ในรายการ `RULES` ส่วน [`register.tsx`](../pdpa-thai/hooks/register.tsx) แสดงฮุกแต่ละตัวและสิ่งที่ฮุกนั้นเขียนทับ
2. **รันชุดทดสอบ** จากโฟลเดอร์รากของที่เก็บโค้ด
   ```bash
   claude plugin test pdpa-thai
   ```
   ค่าตัวอย่างใน [`pdpa-thai/tests/`](../pdpa-thai/tests/) เป็นค่าสมมติ บางค่าประกอบจากชิ้นส่วนย่อย บางค่าเห็นได้ชัดว่าเป็นค่าสมมติ และบางค่าต้องมีรูปแบบถูกต้อง เช่น เลขตรวจสอบถูกต้อง เพื่อให้กฎตรวจพบ
3. **ตรวจว่ามอดเรียกใช้อะไรบ้าง**
   ```bash
   claude plugin validate pdpa-thai
   ```
   บรรทัด `calls:` คือผลการวิเคราะห์โค้ดแบบสถิต (static analysis) ของเอนจิน (engine) ของ Claude Code เองว่าแต่ละโมดูลเรียกใช้เอนจินอย่างไรบ้าง สำหรับ pdpa-thai ได้แก่ นาฬิกา การลงทะเบียนคำสั่ง สถานะของมอดเอง และหน้าจอ (แถบสถานะ ข้อความแจ้ง และการวาด) โดยไม่มีการเรียกเครือข่าย โปรเซส โมเดล หรือ MCP
4. **ทราบว่า CI ตรวจอะไร** [`.github/workflows/test.yml`](../.github/workflows/test.yml) ตรวจความถูกต้องของทุกมอด รันชุดทดสอบ และทำการตรวจเฉพาะในเครื่อง (local-only) 2 รายการ ได้แก่ การค้นหาข้อความในโค้ดฮุกของทุกมอดว่ามีการเรียกเครือข่าย โปรเซส โมเดล หรือ MCP หรือ `fetch(` หรือไม่ และการตรวจว่าการเรียกเอนจินทุกรายการในบรรทัด `calls:` ที่ `claude plugin validate pdpa-thai` แสดง เป็นการเรียกกลุ่ม state, ui, clock หรือ command เท่านั้น (ข้อ 3) การตรวจทั้งสองไม่ได้ทดแทนการอ่านโค้ด และไม่ได้พิสูจน์สิ่งใดเกี่ยวกับมอดอื่นหรือตัว Claude Code เอง รายละเอียดของการตรวจทั้งสองและสิ่งที่ไม่ครอบคลุมอธิบายไว้แห่งเดียวในหัวข้อ [สิ่งที่ CI ตรวจ](../CONTRIBUTING.md#สิ่งที่-ci-ตรวจ)
5. **ทดลองด้วยข้อมูลปลอม** ในโหมด `redact` ให้ส่งพรอมต์ที่มี `password: not-a-real-one` หรือ `ศาสนา: ตัวอย่าง` แล้วดูข้อความแจ้งและป้ายแทนค่าในบันทึกบทสนทนา
