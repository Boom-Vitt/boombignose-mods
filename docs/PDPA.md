# PDPA กับการใช้ผู้ช่วยเขียนโค้ด AI เช่น Claude Code

**ไทย** · [English](PDPA.en.md)

> [!IMPORTANT]
> - เอกสารนี้**ไม่ใช่คำแนะนำทางกฎหมาย** (legal advice) เป็นข้อมูลประกอบสำหรับนักพัฒนาเท่านั้น หากต้องตัดสินใจในประเด็นกฎหมาย โปรดปรึกษาทนายความที่มีคุณสมบัติเหมาะสม หรือเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (Data Protection Officer, DPO) ขององค์กร และสอบถามการตีความอย่างเป็นทางการจากสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล (PDPC)
> - โครงการนี้เป็นโครงการชุมชนที่ไม่เป็นทางการ ดูแลโดยนักพัฒนาเพียงคนเดียวในนามส่วนตัว **ไม่มีส่วนเกี่ยวข้อง ไม่ได้รับการสนับสนุน และไม่ได้รับการรับรอง** จาก Anthropic, PDPC, สำนักงานพัฒนาธุรกรรมทางอิเล็กทรอนิกส์ (ETDA), สำนักงานพัฒนารัฐบาลดิจิทัล (DGA), กระทรวงดิจิทัลเพื่อเศรษฐกิจและสังคม (MDES) หรือหน่วยงานรัฐใดของไทย Claude และ Claude Code เป็นผลิตภัณฑ์ของ Anthropic การกล่าวถึงชื่อในเอกสารนี้มีไว้เพื่อระบุว่ามอดนี้ใช้งานร่วมกับอะไรเท่านั้น
> - การติดตั้ง pdpa-thai ไม่ได้ทำให้องค์กรปฏิบัติตามพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA) มอดนี้ออกแบบมาเพื่อช่วยลดความเสี่ยงเท่านั้น
> - ซอฟต์แวร์นี้ให้ไว้ตามสภาพ (as is) โดยไม่มีการรับประกันใด ๆ ภายใต้[สัญญาอนุญาต MIT](../LICENSE) ผู้ใช้ยังคงรับผิดชอบต่อการจัดการข้อมูลส่วนบุคคลของตน
> - ข้อมูลกฎหมายและหน่วยงานในเอกสารนี้ตรวจสอบเมื่อ 4 ตุลาคม 2569 กฎหมายและประกาศอาจเปลี่ยนแปลงได้ โปรดตรวจจากต้นฉบับทุกครั้ง

## วัตถุประสงค์ของเอกสาร

เอกสารนี้เขียนสำหรับนักพัฒนาและทีมขนาดเล็กในประเทศไทยที่ใช้ผู้ช่วยเขียนโค้ดด้วย AI บนคลาวด์ (cloud AI coding assistant) เช่น Claude Code โดยอธิบาย

1. ช่องทางที่ข้อมูลส่วนบุคคลมักติดไปกับพรอมต์ (prompt) โดยไม่ได้ตั้งใจ
2. บทบัญญัติของพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA) ที่เกี่ยวข้อง เฉพาะส่วนที่ได้ตรวจสอบจากแหล่งต้นฉบับแล้ว
3. สิ่งที่ pdpa-thai ทำ และสิ่งที่ไม่ได้ทำ
4. เช็กลิสต์ที่นำไปใช้ได้ทันที

เอกสารนี้ไม่ครอบคลุมบทลงโทษ ค่าปรับ หรือกำหนดเวลาตามกฎหมาย และไม่ใช่แผนการปฏิบัติตาม PDPA ขององค์กร

## เหตุที่พรอมต์อาจมีข้อมูลส่วนบุคคล

ในแต่ละรอบการทำงาน Claude Code ส่งบทสนทนาไปประมวลผลที่ผู้ให้บริการโมเดลที่ตั้งค่าไว้ (โดยค่าเริ่มต้นคือ Anthropic หรืออาจเป็นแพลตฟอร์มคลาวด์ เช่น Amazon Bedrock หรือ Google Cloud Vertex AI หากองค์กรตั้งค่าไว้) บทสนทนานี้ไม่ได้มีเพียงข้อความที่ผู้ใช้พิมพ์ แต่รวมถึงเนื้อหาของไฟล์ที่ Claude อ่าน ผลลัพธ์ของคำสั่งที่ Claude รัน ไฟล์ `CLAUDE.md` และบริบท (context) อื่นที่ Claude Code แนบไปกับคำขอ ดังนั้นสิ่งใดที่ Claude อ่านได้ ก็อาจกลายเป็นส่วนหนึ่งของสิ่งที่ถูกส่งออกไป

แหล่งที่ข้อมูลส่วนบุคคลมักติดไปด้วย

| แหล่ง | ตัวอย่างสิ่งที่มักติดไป |
| --- | --- |
| โค้ดและข้อมูลทดสอบ (test fixtures, seed data) | ข้อมูลลูกค้าจริงที่ถูกคัดลอกมาเป็นตัวอย่าง |
| บันทึกของระบบ (logs) | อีเมล หมายเลข IP เบอร์โทรศัพท์ หรือโทเค็นเซสชัน (session token) ที่ถูกบันทึกไว้ |
| ไฟล์ส่งออกจากฐานข้อมูล (database dump) และ CSV | ตารางผู้ใช้หรือคำสั่งซื้อทั้งตาราง |
| แชตและทิกเก็ตแจ้งปัญหาจากลูกค้า (support ticket) | ชื่อ ที่อยู่ หรือเลขบัญชีที่ลูกค้าพิมพ์มา |
| `CLAUDE.md` และไฟล์ context อื่น | ช่องทางติดต่อของทีม หรือข้อมูลเข้าถึงเซิร์ฟเวอร์ |
| ผลลัพธ์ของคำสั่ง (command output) | ผลการสืบค้น (query) ฐานข้อมูลที่ใช้งานจริง หรือผลการเรียก API ที่คืนข้อมูลผู้ใช้ |
| รูปภาพและเอกสาร | ภาพหน้าจอระบบหลังบ้าน หรือไฟล์ PDF ที่มีข้อมูลลูกค้า |

กรณีส่วนใหญ่เกิดขึ้นโดยไม่ตั้งใจ เช่น ผู้ใช้ขอให้ Claude แก้บั๊ก Claude จึงเปิดอ่านไฟล์ log เพื่อหาสาเหตุ และไฟล์ log นั้นมีอีเมลของลูกค้าอยู่

## บทบัญญัติที่เกี่ยวข้อง

ตารางต่อไปนี้สรุปเฉพาะมาตราของพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 ที่ได้ตรวจสอบจาก[ฉบับ PDF ที่เผยแพร่บนเว็บไซต์ PDPC](https://www.pdpc.or.th/wp-content/uploads/2023/12/1_Personal-Data-Protection-2562.pdf) (ตรวจสอบเมื่อ 4 ตุลาคม 2569) คำอธิบายเป็นการสรุปความ ไม่ใช่ตัวบทกฎหมาย โปรดอ่านตัวบทจากต้นฉบับ

| มาตรา | เรื่อง | ความเกี่ยวข้องกับการใช้ AI |
| --- | --- | --- |
| 6 | นิยามคำสำคัญ เช่น ข้อมูลส่วนบุคคล ผู้ควบคุมข้อมูลส่วนบุคคล (data controller) และผู้ประมวลผลข้อมูลส่วนบุคคล (data processor) | ข้อมูลส่วนบุคคลคือข้อมูลที่ทำให้ระบุตัวบุคคลได้ ทั้งทางตรงและทางอ้อม จึงกว้างกว่าเลขประจำตัวประชาชนหรือเบอร์โทรศัพท์ |
| 19 | ความยินยอม (consent) หลักทั่วไปคือการเก็บรวบรวม ใช้ หรือเปิดเผยข้อมูลส่วนบุคคลต้องได้รับความยินยอม เว้นแต่ พ.ร.บ. นี้หรือกฎหมายอื่นให้กระทำได้ | การนำข้อมูลลูกค้าไปให้เครื่องมือ AI ประมวลผลอาจถือเป็นการใช้หรือเปิดเผยข้อมูล ควรสอบถาม DPO ว่าการใช้งานนี้อยู่ภายใต้ฐานทางกฎหมาย (lawful basis) ที่องค์กรใช้อยู่หรือไม่ |
| 26 | ข้อมูลส่วนบุคคลที่อ่อนไหว (sensitive data) | มีเงื่อนไขเข้มงวดกว่าข้อมูลทั่วไป ดู[หัวข้อมาตรา 26](#ข้อมูลอ่อนไหวตามมาตรา-26) |
| 28–29 | การส่งหรือโอนข้อมูลส่วนบุคคลไปต่างประเทศ | ดู[หัวข้อการส่งข้อมูลไปต่างประเทศ](#การส่งข้อมูลไปต่างประเทศและการประมวลผลบนคลาวด์) |
| 37 | หน้าที่ของผู้ควบคุมข้อมูลส่วนบุคคล รวมถึงการจัดให้มีมาตรการรักษาความมั่นคงปลอดภัยที่เหมาะสม | การเลือกว่าเครื่องมือใดเข้าถึงข้อมูลส่วนบุคคลได้ อาจเป็นส่วนหนึ่งของการพิจารณาด้านความมั่นคงปลอดภัย |
| 40 | หน้าที่ของผู้ประมวลผลข้อมูลส่วนบุคคล | ทีมที่พัฒนาหรือดูแลระบบให้ลูกค้าอาจอยู่ในฐานะผู้ประมวลผลข้อมูลส่วนบุคคล ควรอ่านมาตรานี้ประกอบกับสัญญาที่มีกับลูกค้า |

## การส่งข้อมูลไปต่างประเทศและการประมวลผลบนคลาวด์

- มาตรา 28 ว่าด้วยการส่งหรือโอนข้อมูลส่วนบุคคลไปยังต่างประเทศ ซึ่งเกี่ยวข้องกับมาตรฐานการคุ้มครองข้อมูลของปลายทางตามหลักเกณฑ์ที่คณะกรรมการคุ้มครองข้อมูลส่วนบุคคลประกาศกำหนด และมาตรา 29 กำหนดกรณีเพิ่มเติมของการส่งหรือโอนข้อมูลไปต่างประเทศ
- ประกาศที่ออกตามมาตรา 28 (พ.ศ. 2566): [หน้าประกาศ](https://www.pdpc.or.th/2500/) และ [ไฟล์ PDF](https://www.pdpc.or.th/wp-content/uploads/2024/01/M28.pdf)
- ประกาศที่ออกตามมาตรา 29: [หน้าประกาศ](https://www.pdpc.or.th/2507/)

เมื่อใช้บริการ AI บนคลาวด์ จะเกิดคำถามว่าการส่งพรอมต์ที่มีข้อมูลส่วนบุคคลไปยังบริการนั้นถือเป็นการ "ส่งหรือโอน" ข้อมูลไปต่างประเทศตามมาตราดังกล่าวหรือไม่ คำตอบ**ขึ้นอยู่กับข้อเท็จจริง** โดยเฉพาะว่าบุคคลที่สามเข้าถึงข้อมูลได้หรือไม่ เอกสารนี้**ไม่สรุป**ประเด็นนี้

แนวทางในทางปฏิบัติ

- สอบถาม DPO หรือทนายความขององค์กร
- ตรวจข้อกำหนดและสัญญากับผู้ให้บริการ เช่น สถานที่ประมวลผล ผู้ที่เข้าถึงข้อมูลได้ และระยะเวลาการเก็บรักษา
- ตรวจว่าองค์กรมีข้อตกลงกับผู้ให้บริการ AI อยู่แล้วหรือไม่
- ลดข้อมูลตั้งแต่ต้นทางตามหลักการใช้ข้อมูลเท่าที่จำเป็น (data minimisation) ข้อมูลที่ไม่ถูกส่งออกไปย่อมช่วยลดขอบเขตของคำถามนี้ในทางปฏิบัติ

## มาตรการรักษาความมั่นคงปลอดภัยและการแจ้งเหตุละเมิด

- มาตรา 37 กำหนดหน้าที่ของผู้ควบคุมข้อมูลส่วนบุคคล รวมถึงการจัดให้มีมาตรการรักษาความมั่นคงปลอดภัยที่เหมาะสม
- คณะกรรมการคุ้มครองข้อมูลส่วนบุคคลออกประกาศเรื่องมาตรการรักษาความมั่นคงปลอดภัย (พ.ศ. 2565): [หน้าประกาศ](https://www.pdpc.or.th/2971/) โปรดอ่านข้อกำหนดจากประกาศโดยตรง เอกสารนี้ไม่สรุปเนื้อหาของประกาศ
- pdpa-thai ออกแบบมาเพื่อช่วยลดข้อมูลที่ส่งให้เครื่องมือ AI ในทางเทคนิค เอกสารนี้ไม่ได้ประเมินว่า pdpa-thai เข้าข่ายมาตรการตามมาตรา 37 หรือตามประกาศข้างต้นหรือไม่ และไม่ได้แทนมาตรการอื่นขององค์กร

หากข้อมูลส่วนบุคคลถูกส่งไปยังปลายทางที่ไม่ควรได้รับ ให้ปฏิบัติตามกระบวนการรับมือเหตุละเมิดขององค์กร และดูหน้าของ PDPC เรื่อง[การแจ้งเหตุละเมิดข้อมูลส่วนบุคคล](https://www.pdpc.or.th/2405/) และ[แบบแจ้งเหตุ](https://www.pdpc.or.th/17259/) เอกสารนี้ไม่ได้ระบุเงื่อนไขและระยะเวลาการแจ้ง โปรดตรวจจากต้นฉบับ

## ข้อมูลอ่อนไหวตามมาตรา 26

มาตรา 26 ระบุประเภทข้อมูลส่วนบุคคลที่กฎหมายคุ้มครองเข้มงวดกว่าข้อมูลทั่วไป (มักเรียกว่าข้อมูลอ่อนไหว) ได้แก่ เชื้อชาติ เผ่าพันธุ์ ความคิดเห็นทางการเมือง ความเชื่อในลัทธิ ศาสนาหรือปรัชญา พฤติกรรมทางเพศ ประวัติอาชญากรรม ข้อมูลสุขภาพ ความพิการ ข้อมูลสหภาพแรงงาน ข้อมูลพันธุกรรม ข้อมูลชีวภาพ และข้อมูลอื่นที่กระทบต่อเจ้าของข้อมูลในทำนองเดียวกันตามที่คณะกรรมการประกาศกำหนด ข้อมูลกลุ่มนี้มักพบในระบบงานบุคคล (HR) ระบบสุขภาพ และระบบประกันภัย

### เหตุที่ pdpa-thai ตรวจข้อมูลกลุ่มนี้เฉพาะเมื่อมีป้ายกำกับ

นิพจน์ปรกติ (regular expression) ไม่สามารถอ่านประโยคทั่วไปแล้วตัดสินได้อย่างน่าเชื่อถือว่าประโยคนั้นเปิดเผยข้อมูลสุขภาพหรือศาสนาของบุคคล หากตรวจทุกคำที่เกี่ยวข้อง pdpa-thai จะปกปิดเอกสาร โค้ด และข้อความทั่วไปจำนวนมากโดยไม่จำเป็น pdpa-thai จึงตรวจข้อมูลมาตรา 26 **เฉพาะเมื่อเขียนในรูปแบบ `ป้ายกำกับ: ค่า`** (label: value) คือมีป้ายกำกับภาษาไทยหรืออังกฤษ ตามด้วยเครื่องหมายทวิภาค (`:` หรือ `：` แบบเต็มความกว้าง) หรือเครื่องหมายเท่ากับ (`=`) แล้วจึงเป็นค่า รูปแบบนี้พบบ่อยในข้อมูลจากแบบฟอร์ม ไฟล์ JSON และไฟล์ YAML ส่วนไฟล์ CSV และไฟล์ SQL dump ซึ่งป้ายกำกับอยู่ในแถวหัวตารางหรือรายการคอลัมน์ ไม่ได้อยู่ติดกับค่า **จะไม่ถูกตรวจพบ** ไม่ควรพึ่ง pdpa-thai เพื่อให้ Claude อ่านเวชระเบียนหรือข้อมูลงานบุคคลจริงได้อย่างปลอดภัย ควรเก็บข้อมูลเหล่านี้ไว้นอกเซสชัน

- เมื่อพบ pdpa-thai จะคงป้ายกำกับไว้และแทนค่าด้วยป้ายแทนค่า (placeholder) เช่น `[REDACTED:SENSITIVE_1~k3x9q]` ค่าจะสิ้นสุดที่ตัวคั่นตัวแรกที่พบ ได้แก่ เครื่องหมายจุลภาค อัฒภาค เครื่องหมายคำพูด วงเล็บปีกกาปิด หรือการขึ้นบรรทัดใหม่ หากค่าเป็นรายการ ส่วนที่เหลือของรายการ**จะไม่ถูกปกปิด** เช่น หากระบุโรคสองโรคคั่นด้วยจุลภาค จะมีเพียงโรคแรกที่ถูกแทน และค่าที่ขึ้นต้นด้วย `[` หรือ `{` (อาร์เรย์หรืออ็อบเจกต์ JSON) จะไม่ถูกตรวจเลย จึงไม่มีส่วนใดในค่านั้นถูกแทน เว้นแต่กฎอื่น เช่น `PHONE` หรือ `EMAIL` ตรวจพบ
- ตัวอย่างป้ายกำกับภาษาไทย: เชื้อชาติ ศาสนา ความคิดเห็นทางการเมือง ประวัติอาชญากรรม โรคประจำตัว ประวัติการรักษา ความพิการ สหภาพแรงงาน ข้อมูลพันธุกรรม ข้อมูลชีวภาพ
- ตัวอย่างป้ายกำกับภาษาอังกฤษ: race, religion, political opinion, criminal record, medical history, diagnosis, disability, trade union, genetic data, biometric data
- ข้อความบรรยายทั่วไปที่เล่าถึงอาการป่วยหรือความเชื่อของบุคคล**จะไม่ถูกตรวจพบ**
- ข้อมูลชีวภาพในรูปไฟล์ภาพ เช่น ภาพใบหน้า **จะไม่ถูกตรวจ** เพราะ pdpa-thai ไม่ตรวจรูปภาพ

รายการป้ายกำกับทั้งหมดอยู่ใน [DETECTION.md](DETECTION.md)

## สิ่งที่ pdpa-thai ทำ

pdpa-thai (เวอร์ชัน 0.3.0) เป็นมอด (mod) ของ Claude Code ต้องใช้ Claude Code รุ่นที่รองรับปลั๊กอินแบบ hook module และทดสอบแล้วกับ Claude Code 2.1.289 เท่านั้น API ของ hook ยังอยู่ในระยะเปิดให้ใช้ก่อน (early access) Claude Code รุ่นที่เก่ากว่าหรือใหม่กว่าจึงอาจข้ามการป้องกันบางส่วนหรือทั้งหมดโดยไม่แจ้งเตือน และป้าย (badge) ของ CI แสดงเพียงว่าเทสต์หน่วย (unit test) ผ่านบน Claude Code รุ่นล่าสุด ในทางเทคนิค pdpa-thai ออกแบบมาเพื่อช่วยลดข้อมูลที่ส่งออกไป ตามหลักการใช้ข้อมูลเท่าที่จำเป็น ซึ่งเป็นแนวปฏิบัติทั่วไปด้านความเป็นส่วนตัว pdpa-thai จะนับเป็นมาตรการตาม พ.ร.บ. หรือประกาศใดหรือไม่ เป็นเรื่องที่องค์กรและ DPO ต้องพิจารณา

- **ตรวจหาข้อมูล 12 ชนิด โดยไม่รับประกันผล (best effort)** ได้แก่ `THAI_ID` `CARD` `PHONE` `EMAIL` `IP` `SECRET` `PASSPORT` `BANK_ACCOUNT` `DOB` `SENSITIVE` `ADDRESS` และ `NAME` ด้วยกฎที่ทำงานภายในโปรเซสของ Claude Code รายละเอียดและข้อจำกัดของแต่ละกฎอยู่ใน [DETECTION.md](DETECTION.md)
- **โหมด `redact` (ค่าเริ่มต้น)** แทนค่าที่ตรวจพบด้วยป้ายแทนค่า เช่น `[REDACTED:PHONE_1~k3x9q]` **ก่อน**ที่โมเดลจะเห็น ภายในข้อความเดียวกัน ค่าเดียวกันจะได้ป้ายแทนค่าเดียวกัน โมเดลจึงยังอ้างถึงได้ แต่ลำดับเลขจะเริ่มใหม่ในแต่ละข้อความ `PHONE_1` ในสองข้อความจึงอาจเป็นคนละค่า โหมดนี้ครอบคลุม
  - พรอมต์ที่ผู้ใช้พิมพ์
  - ผลลัพธ์ของเครื่องมือ (เนื้อหาไฟล์และผลลัพธ์ของคำสั่ง) และเนื้อหาอื่นที่บทสนทนาเก็บไว้ให้โมเดลอ่าน เช่น บริบทที่ฮุก (hook) อื่นเพิ่มเข้ามา
  - ไฟล์ที่แนบด้วย `@` รวมถึงไฟล์ `CLAUDE.md` และ context block อื่นที่แนบกับข้อความแรก
- **โหมด `block`** ไม่ส่งพรอมต์ที่ผู้ใช้พิมพ์ หากพรอมต์นั้นมีข้อมูลที่ตรวจพบ และยังคงปกปิดผลลัพธ์ของเครื่องมือและเนื้อหาอื่นเช่นเดียวกับโหมด `redact`
- **โหมด `off`** ปิดการปกปิดและการตรวจการเรียกเครื่องมือ (การพรางบนหน้าจอควบคุมแยกด้วย `/pdpa-blur`)
- **ปฏิเสธการเรียกเครื่องมือ (tool call)** ที่มีป้ายแทนค่าซึ่งออกในเซสชันนี้ เพื่อลดโอกาสที่ป้ายแทนค่าจะถูกเขียนลงไฟล์หรือคำสั่งจริงโดยไม่ตั้งใจ การตรวจนี้ทำงานเฉพาะเมื่อเปิดการป้องกัน (โหมด `redact` หรือ `block`) และจับเฉพาะป้ายแทนค่าที่มีส่วนต่อท้าย (suffix) ของเซสชันนี้ครบถ้วน ป้ายจากเซสชันก่อน หรือป้ายที่ถูกพิมพ์ใหม่โดยไม่มีส่วนต่อท้าย จะไม่ถูกปฏิเสธ
- **`/pdpa-blur [on | off | record]`** ควบคุมการพรางบนหน้าจอ โดยเปิดไว้เป็นค่าเริ่มต้น หากไม่ระบุอาร์กิวเมนต์จะสลับสถานะ (เปิดหากปิดอยู่ ปิดหากเปิดอยู่หรืออยู่ในโหมดบันทึกหน้าจอ) ส่วนอาร์กิวเมนต์อื่นจะไม่เปลี่ยนการตั้งค่าใด และแสดงเพียงบรรทัดวิธีใช้ (usage) ข้อมูลที่ตรวจพบในข้อความของผู้ใช้และของ Claude จะแสดงเป็นสีเทาบนพื้นเทา และวางเมาส์เพื่อดู ในโหมด `redact` พรอมต์ที่ส่งแล้วจะแสดงเป็นป้ายแทนค่าอยู่แล้ว และในโหมด `block` พรอมต์ที่มีข้อมูลที่ตรวจพบจะไม่ถูกส่ง การพรางจึงมีผลหลักกับข้อความของ Claude และข้อความที่ส่งขณะปิดการป้องกัน ใช้ได้เฉพาะบนเทอร์มินัลและแอปเดสก์ท็อป ไม่ครอบคลุมผลลัพธ์ของเครื่องมือ และไม่พรางข้อความที่ยาวเกิน 100,000 ตัวอักษร การคัดลอก การเลือกข้อความ โปรแกรมอ่านหน้าจอ การค้นหาในเทอร์มินัล และการบันทึกหรือ log ของเทอร์มินัล (เช่น tmux หรือ asciinema) ยังได้ค่าจริง ส่วนวิดีโอบันทึกหน้าจอจะเห็นค่าจริงเมื่อวางเมาส์บนข้อความนั้น เทอร์มินัลที่ปรับความต่างของสีอัตโนมัติ (เช่น เทอร์มินัลใน VS Code ซึ่งเปิดการตั้งค่า minimum contrast ratio ไว้โดยค่าเริ่มต้น) อาจแสดงข้อความที่พรางไว้ให้อ่านได้ การพรางนี้เป็นเพียงการปิดบังทางสายตา ไม่เปลี่ยนสิ่งที่ส่งให้โมเดล
- **`/pdpa-blur record`** (โหมดบันทึกหน้าจอ) ใช้สำหรับการบันทึกวิดีโอหน้าจอและการแชร์หน้าจอ การพรางยังเปิดอยู่ การวางเมาส์จะไม่เปิดค่าที่พรางไว้ตลอดเวลาที่อยู่ในโหมดนี้ และแถบสถานะจะแสดง `PDPA: <โหมด> · REC` โหมดนี้พรางเฉพาะค่าที่ตรวจพบในข้อความของผู้ใช้และข้อความของ Claude ส่วนสิ่งอื่นที่ Claude Code แสดง เช่น การเรียกเครื่องมือ (tool call) และผลลัพธ์ ส่วนต่างของไฟล์ (diff) การคิดของโมเดล (thinking) ข้อความแจ้งเตือน และแผงอื่น จะแสดงตามปกติ โหมดนี้ไม่ครอบคลุมข้อมูลส่วนบุคคลที่กฎตรวจไม่พบ เช่น ชื่อที่ไม่มีป้ายกำกับหรือคำนำหน้าชื่อ ซึ่งจะแสดงตามจริง ข้อความที่กำลังพิมพ์ในช่องพรอมต์ก่อนกดส่ง (ตัวป้องกันแทนค่าเมื่อกดส่งเท่านั้น) การเรียกเครื่องมือ ผลลัพธ์ของเครื่องมือ และผลลัพธ์ของคำสั่งบนหน้าจอ ข้อความต้นฉบับที่ปรากฏบนหน้าจอด้วยเหตุอื่น (เช่น ไฟล์ที่เปิดอยู่ในหน้าต่างอื่น) การเลือกข้อความ ซึ่งอาจทำให้ข้อความที่พรางไว้อ่านได้บนหน้าจอ และการคัดลอกซึ่งยังได้ข้อความจริง ก่อนบันทึกหน้าจอ ให้ตั้งตัวป้องกันเป็นโหมด `redact` หรือ `block` สั่ง `/pdpa-blur record` และตรวจวิดีโอที่บันทึกไว้ก่อนแชร์ การพรางนี้เป็นเพียงการปิดบังทางสายตา ไม่ใช่หลักประกัน

โหมดและการตั้งค่าการพรางไม่ได้บันทึกลงดิสก์ และจะเริ่มที่โหมด `redact` พร้อมเปิดการพรางและปิดโหมดบันทึกหน้าจอทุกครั้งที่เริ่ม Claude Code ส่วน `/clear` จะคงโหมดปัจจุบันไว้หรือไม่นั้น ผู้ดูแลโครงการยังไม่ได้ตรวจสอบ (ดูโหมดปัจจุบันได้โดยใช้ `/pdpa-guard` โดยไม่ระบุอาร์กิวเมนต์ หรือดูที่แถบสถานะ)

**ตรวจว่ามอดทำงานอยู่** เมื่อเปิดการป้องกัน แถบสถานะ (status line) จะแสดง `PDPA: redact` หรือ `PDPA: block` (ตามด้วย ` · REC` ในโหมดบันทึกหน้าจอ) หากไม่แสดงค่าใดในสองค่านี้ แสดงว่าไม่มีการปกปิด โดย `PDPA: off` หมายถึงปิดการป้องกันอยู่ และหากไม่มีข้อความ `PDPA:` เลย แสดงว่ามอดไม่ได้ถูกโหลด (ใช้ `claude --debug` เพื่อดูสาเหตุ) การรันแบบไม่มีหน้าจอโต้ตอบ (headless เช่น `claude -p`) ไม่มีแถบสถานะ จึงใช้แถบสถานะยืนยันการป้องกันในกรณีนั้นไม่ได้

### ข้อเท็จจริงด้านความเป็นส่วนตัว

- การตรวจหาทำงานภายในโปรเซสของ Claude Code บนเครื่องของผู้ใช้ หรือบนเครื่องที่เซสชันบนคลาวด์หรือเซสชันระยะไกลทำงานอยู่
- pdpa-thai ไม่เรียกเครือข่าย โปรเซส โมเดล หรือ MCP ด้วยตนเอง โค้ดใช้เพียงนาฬิกา การลงทะเบียนคำสั่ง สถานะของเซสชันของตนเอง และการแสดงผลบนหน้าจอ ทุกครั้งที่มีการ push และ pull request CI จะทำการตรวจเฉพาะในเครื่อง (local-only) 2 รายการ ได้แก่ การค้นหาข้อความในโค้ดฮุกของทุกมอดว่ามีการเรียกเครือข่าย โปรเซส โมเดล หรือ MCP หรือ `fetch(` หรือไม่ และการตรวจว่าการเรียกเอนจินทุกรายการในบรรทัด `calls:` ที่ `claude plugin validate pdpa-thai` แสดง เป็นการเรียกกลุ่ม state, ui, clock หรือ command เท่านั้น การตรวจทั้งสองไม่ได้พิสูจน์สิ่งใดเกี่ยวกับมอดอื่นหรือตัว Claude Code เอง รายละเอียดของการตรวจทั้งสองและสิ่งที่ไม่ครอบคลุมอธิบายไว้แห่งเดียวในหัวข้อ [สิ่งที่ CI ตรวจ](../CONTRIBUTING.md#สิ่งที่-ci-ตรวจ) ส่วนมอด agents-panel จะเริ่มเอเจนต์ย่อย (subagent) เฉพาะเมื่อผู้ใช้กดปุ่ม ▶ run และเอเจนต์ย่อยนั้นติดต่อผู้ให้บริการโมเดลที่ตั้งค่าไว้ (โดยค่าเริ่มต้นคือ Anthropic) เช่นเดียวกับเอเจนต์ทั่วไป อ่านโค้ดได้ที่ [`pdpa-thai/hooks/`](../pdpa-thai/hooks/)
- **บทสนทนาที่ปกปิดแล้วยังคงถูกส่งไปยังผู้ให้บริการโมเดลที่ตั้งค่าไว้ (โดยค่าเริ่มต้นคือ Anthropic)** เช่นเดียวกับบทสนทนา Claude Code ทั่วไป สิ่งที่ไม่อยู่ในคำขอที่ส่งไปยังผู้ให้บริการโมเดลคือเฉพาะตำแหน่งที่ถูกแทนค่าแล้ว หากค่าเดียวกันปรากฏในส่วนที่ pdpa-thai ไม่ได้แก้ไข (ดู[สิ่งที่ pdpa-thai ไม่ได้ทำ](#สิ่งที่-pdpa-thai-ไม่ได้ทำ)) ค่านั้นจะยังถูกส่งออกไป ส่วนข้อมูลที่กฎตรวจไม่พบจะถูกส่งไปตามเดิม
- **การปกปิดมีผลกับสำเนาที่โมเดลอ่าน ไม่ใช่ทุกสำเนา** มอดนี้แก้ไขเฉพาะสิ่งที่ Claude Code ส่งให้โมเดล ช่องทางอื่นเป็นช่องทางแยกต่างหาก ไม่อยู่ในขอบเขตของมอด และอาจได้รับค่าเดิม ได้แก่ Remote Control (ซึ่งส่งต่อผ่านบริการของ Anthropic ไปยัง claude.ai หรือแอป Claude) hook แบบคำสั่ง (command hook) ในการตั้งค่าของผู้ใช้ ระบบรวบรวม telemetry ที่องค์กรตั้งค่าไว้ และรายงานที่ผู้ใช้ส่งให้ Anthropic ส่วนไคลเอนต์ SDK ที่เซสชันส่งสตรีมไปให้ (SDK stream) ก็อาจเห็นข้อความในรูปเดิมชั่วครู่ก่อนถูกปกปิด ไฟล์ที่ Claude Code จัดเก็บเองยังเก็บค่าเดิมบางส่วนเป็นข้อมูลดิบ (ดูด้านล่าง) และ pdpa-thai ทำงานในที่ที่ Claude Code ทำงาน หากเป็นเซสชันบนคลาวด์ ไม่ใช่เครื่องของผู้ใช้ ค่าเดิมจะอยู่บนเครื่องคลาวด์นั้นอยู่แล้ว

## สิ่งที่ pdpa-thai ไม่ได้ทำ

### ด้านกฎหมายและองค์กร

- ไม่ได้ให้หรือแทนความยินยอม และไม่ได้สร้างฐานทางกฎหมายสำหรับการประมวลผล
- ไม่แทนสัญญาประมวลผลข้อมูล (data processing agreement) ประกาศความเป็นส่วนตัว (privacy notice) บันทึกรายการกิจกรรมการประมวลผล (records of processing) DPO หรือกระบวนการรับมือและแจ้งเหตุละเมิด
- ไม่ได้ตอบคำถามว่าการใช้บริการ AI บนคลาวด์เป็นการโอนข้อมูลไปต่างประเทศหรือไม่
- ไม่ได้ทำให้องค์กรปฏิบัติตาม PDPA โปรดศึกษาหน้าที่ข้างต้นจาก พ.ร.บ. และขอคำปรึกษาจากผู้เชี่ยวชาญ
- ไม่ได้ทำให้ข้อมูลเป็นข้อมูลนิรนาม (anonymisation) การปกปิดเป็นเพียงการแทนค่าที่ตรวจพบ บทสนทนาที่ปกปิดแล้วอาจยังทำให้ระบุตัวบุคคลได้ทั้งทางตรงและทางอ้อม (มาตรา 6) จึงอาจยังเป็นข้อมูลส่วนบุคคล และคำถามเรื่องฐานทางกฎหมายและการส่งข้อมูลไปต่างประเทศยังคงต้องพิจารณา โปรดสอบถาม DPO
- ไม่ใช่มาตรการควบคุมระดับองค์กร มอดทำงานแยกตามผู้ใช้และตามเครื่อง ผู้ใช้ปิดได้เองทุกเมื่อ (`/pdpa-guard off` หรือปิดการใช้งานปลั๊กอิน) ไม่มีการตั้งค่าที่ผู้ดูแลระบบล็อกได้ และไม่เก็บบันทึกการตรวจสอบ (audit record) ว่าปกปิดหรือส่งอะไรไป จึงบังคับใช้จากส่วนกลางไม่ได้ และใช้แสดงว่ามีมาตรการควบคุมอยู่จริงไม่ได้
- ไม่ได้ป้องกันไม่ให้ Claude Code ส่งบทสนทนา (ที่ปกปิดแล้ว) ไปยังผู้ให้บริการโมเดลที่ตั้งค่าไว้ (โดยค่าเริ่มต้นคือ Anthropic)
- ไม่ได้ควบคุมสิ่งที่ปลั๊กอินอื่น เซิร์ฟเวอร์ MCP หรือคำสั่งที่ Claude รัน ทำกับไฟล์ดิบในเครื่อง คำสั่งยังอ่านไฟล์ดิบและส่งไปที่อื่นได้ pdpa-thai ปกปิดเฉพาะสิ่งที่ส่งกลับมาให้โมเดล
- ไม่ครอบคลุมเครื่องมืออื่น เช่น การแชตกับ AI ผ่านเว็บเบราว์เซอร์ หรือปลั๊กอิน AI ในโปรแกรมแก้ไขโค้ดอื่น

### ด้านเทคนิค

รายการต่อไปนี้เป็นข้อจำกัดชุดเดียวกับหัวข้อ[ข้อจำกัด](../README.md#ข้อจำกัด)ใน README และเรียงลำดับเดียวกัน รายละเอียดอยู่ใน [DETECTION.md](DETECTION.md#ข้อจำกัดที่ทราบ)

- กฎทั้งหมดเป็นนิพจน์ปรกติที่ไม่รับประกันผล **จะมี**ข้อมูลที่ตรวจไม่พบ และ**จะมี**ข้อความทั่วไปบางส่วนถูกปกปิด
- มอดนี้ไม่ใช่เครื่องมือสแกนความลับ (secret scanner) ตรวจพบเฉพาะรูปแบบโทเค็นและป้ายกำกับที่ระบุไว้ใน [DETECTION.md](DETECTION.md#ข้อมูลลับ-secret) และข้ามค่าที่มีลักษณะเป็นโค้ด จึงไม่ควรนำความลับเข้ามาในเซสชัน และควรใช้เครื่องมือสแกนความลับโดยเฉพาะ
- ค่าหลังป้ายกำกับ (`SENSITIVE`, `ADDRESS`, `NAME`) จะสิ้นสุดที่เครื่องหมายจุลภาค อัฒภาค เครื่องหมายคำพูด `}` หรือการขึ้นบรรทัดใหม่ที่พบก่อน ส่วนที่เหลือของที่อยู่หรือรายการจะถูกส่งไปตามที่เขียน ค่าหลังป้ายกำกับที่ขึ้นต้นด้วย `[` หรือ `{` (อาร์เรย์หรืออ็อบเจกต์ JSON) จะไม่ตรงกับกฎกลุ่มนี้เลย มีเพียงกฎอื่น เช่น `PHONE` หรือ `EMAIL` ที่ยังอาจแทนค่าบางส่วนในนั้นได้
- ชื่อและที่อยู่ที่ไม่มีป้ายกำกับหรือคำนำหน้าชื่อ เช่น ชื่อที่ปรากฏกลางประโยค จะตรวจไม่พบ
- ไม่ตรวจเนื้อหาในรูปภาพและเอกสารที่แนบเป็นบล็อกแยก
- Claude Code ไม่เปิดให้มอดแก้ไขเนื้อหาบางส่วน จึงไม่มีการปกปิดในส่วนนั้น ได้แก่ กระบวนการคิดของโมเดล (thinking) และค่าที่ Claude ส่งให้เครื่องมือ (tool_use input)
- ประวัติการสนทนาที่เปิดต่อ (resume) และทรานสคริปต์ (transcript) ของ subagent ที่บันทึกไว้แล้ว มอดจะไม่ตรวจซ้ำ ส่วนที่ไม่ได้ปกปิดในขณะบันทึกจะถูกส่งไปตามเดิม
- ผลลัพธ์ของเครื่องมือแบบมีโครงสร้างและเนื้อหาของไฟล์แนบ (เช่น ไฟล์ที่อ้างถึงด้วย `@`) ที่ Claude Code เก็บไว้ยังคงเป็นค่าเดิมในทรานสคริปต์ และการแสดงผลลัพธ์ของเครื่องมือบนหน้าจอไม่ถูกพราง
- ประวัติพรอมต์ของ Claude Code เอง (ที่เรียกกลับด้วยปุ่มลูกศรขึ้น) อยู่นอกการควบคุมของมอด และอาจเก็บข้อความที่ผู้ใช้พิมพ์ไว้บนเครื่องโดยไม่ปกปิด
- ไม่ตรวจพรอมต์ระบบ (system prompt) เช่น ข้อมูลสภาพแวดล้อม คำแนะนำของเซิร์ฟเวอร์ MCP และส่วนที่ปลั๊กอินอื่นเพิ่มเข้าไป รวมถึงคำอธิบายของเครื่องมือและ skill
- ไม่มีการปกปิดใน 3 ส่วนต่อไปนี้ ได้แก่ คำตอบของ Claude ข้อความสรุปที่ได้จากการบีบอัดบทสนทนา (compaction) และข้อความแจ้งจากระบบ (notice)
- ค่าที่ถูกแบ่งไว้ในหลายข้อความอาจหลุดการตรวจจับ
- หาก hook ของมอดเกิดข้อผิดพลาด (throw) หรือใช้เวลาเกินที่ Claude Code กำหนดต่อ hook หนึ่งตัว Claude Code จะข้าม hook นั้นและส่งข้อความไปตามเดิมโดยไม่ปกปิดและไม่มีการแจ้งเตือน (fail-open)
- หากมอดไม่ได้โหลด จะไม่มีการปกปิดใด ๆ และสัญญาณเดียวคือไม่มีรายการ `PDPA:` บนแถบสถานะ ให้ใช้ `claude --debug` เพื่อดูสาเหตุ ทั้งนี้การทำงานแบบ headless (เช่น `claude -p`) ไม่มีแถบสถานะ
- API ของ hook ยังอยู่ในระยะทดลองใช้ (early access) มอดนี้ทดสอบแล้วกับ Claude Code 2.1.289 เท่านั้น เวอร์ชันก่อนหน้าหรือใหม่กว่าอาจข้ามการป้องกันบางส่วนหรือทั้งหมดโดยไม่มีการแจ้งเตือน และป้าย (badge) ของ CI แสดงเพียงว่าชุดทดสอบหน่วย (unit test) ผ่านบน Claude Code เวอร์ชันล่าสุด
- hook ของปลั๊กอินอื่นที่ทำงานก่อนมอดนี้อาจเห็นข้อความต้นฉบับ
- ผลลัพธ์ของเครื่องมือและข้อความอื่นในบทสนทนาอาจแสดงในรูปแบบเดิมชั่วครู่ก่อนถูกปกปิด ทั้งบนหน้าจอของผู้ใช้และปลายทางที่เซสชันถูกส่งต่อไปแสดง เช่น Remote Control (ซึ่งส่งต่อผ่านบริการของ Anthropic ไปยัง claude.ai หรือแอป Claude) หรือ SDK stream
- มอดนี้แก้ไขเฉพาะสิ่งที่ Claude Code ส่งให้โมเดล ช่องทางอื่นเป็นช่องทางแยกต่างหาก ไม่อยู่ในขอบเขตของมอด และอาจได้รับค่าเดิม ได้แก่ Remote Control (ซึ่งส่งต่อผ่านบริการของ Anthropic ไปยัง claude.ai หรือแอป Claude) hook แบบคำสั่ง (command hook) ในการตั้งค่าของผู้ใช้ ระบบรวบรวม telemetry ที่องค์กรตั้งค่าไว้ และรายงานที่ผู้ใช้ส่งให้ Anthropic
- การพรางบนหน้าจอเป็นเพียงการปิดบังด้วยสี การคัดลอก การเลือกข้อความ โปรแกรมอ่านหน้าจอ การค้นหาใน terminal และการบันทึกหรือ log ของ terminal (เช่น tmux หรือ asciinema) ยังได้ค่าจริง ส่วนวิดีโอบันทึกหน้าจอจะเห็นค่าจริงเมื่อวางเมาส์บนข้อความนั้น เว้นแต่เปิดโหมดบันทึกหน้าจอ (`/pdpa-blur record`) ไว้ ทั้งนี้โหมดบันทึกหน้าจอไม่ครอบคลุมช่องพรอมต์ก่อนกดส่ง ผลลัพธ์ของเครื่องมือหรือคำสั่ง และข้อความต้นฉบับที่แสดงอยู่ที่อื่น terminal ที่ปรับความต่างของสีอัตโนมัติ (เช่น terminal ใน VS Code ซึ่งเปิดการตั้งค่า minimum contrast ratio ไว้โดยค่าเริ่มต้น) อาจแสดงข้อความที่พรางไว้ให้อ่านได้ การพรางใช้ได้เฉพาะ terminal และแอปเดสก์ท็อป และไม่พรางข้อความที่ยาวเกิน 100,000 ตัวอักษร
- การปฏิเสธการเรียกเครื่องมือจับเฉพาะป้ายแทนค่าของเซสชันนี้ที่เขียนตรงตามรูปแบบเดิม และไม่ทำงานในโหมด `off`
- ข้อความแจ้งเตือนนับเฉพาะรายการที่ตรงกับกฎ การไม่มีข้อความแจ้งเตือนไม่ได้หมายความว่าไม่มีข้อมูลส่วนบุคคลถูกส่งออกไป และการมีข้อความแจ้งเตือนก็ไม่ได้หมายความว่าข้อความนั้นไม่มีข้อมูลส่วนบุคคลเหลืออยู่แล้ว
- Claude เห็นเพียงป้ายแทนค่า จึงใช้ค่าจริงทำงานไม่ได้ และการปกปิดย้อนกลับไม่ได้ การปิดการป้องกันจึงไม่ได้คืนค่าที่ถูกปกปิดไปแล้ว หากงานต้องใช้ค่าจริง ให้ใช้ `/pdpa-guard off` แล้วส่งค่าจริงอีกครั้ง และเปิดกลับด้วย `/pdpa-guard redact` เมื่องานนั้นเสร็จ ระหว่างที่ปิดอยู่ มอดจะไม่ปฏิเสธการเรียกเครื่องมือที่มีป้ายแทนค่าเดิม จึงควรตรวจสิ่งที่ Claude เขียนลงไฟล์
- ข้อมูลที่ส่งออกไประหว่างปิดการป้องกัน (`off`) จะคงอยู่ในบทสนทนาตามเดิม การเปิดการป้องกันกลับไม่ได้ปกปิดย้อนหลัง และข้อมูลนั้นจะถูกส่งซ้ำไปกับทุกคำขอถัดไปในบทสนทนาเดียวกัน หากต้องการตัดออก ให้ใช้ `/clear` หรือเริ่มเซสชันใหม่
- `CLAUDE.md`, context block อื่น และไฟล์แนบ จะคงผลจากครั้งแรกที่ Claude Code เตรียมเนื้อหานั้นไว้ การเปลี่ยนโหมดภายหลังจึงไม่มีผลกับเนื้อหาที่เตรียมไว้แล้ว ทั้งนี้ context block จะถูกเตรียมใหม่หลังใช้ `/clear` หรือหลังการบีบอัดบทสนทนา
- `CLAUDE.md` และ context block อื่นถูกปกปิดด้วย Claude จึงไม่เห็นค่าจริงที่ผู้ใช้ตั้งใจเขียนไว้ เช่น อีเมลของผู้ใช้ใน `CLAUDE.md`
- ข้อมูลที่เปิดเผยต่อสาธารณะอยู่แล้ว เช่น หมายเลขโทรศัพท์ติดต่อของหน่วยงาน ก็ถูกปกปิดหากตรงกับรูปแบบ
- มอดนี้ช่วยลดข้อมูลที่ถูกส่งออกไป แต่ไม่ได้ทำให้ Claude Code หยุดส่งบทสนทนา (ที่ปกปิดแล้ว) ไปยังผู้ให้บริการโมเดลที่ตั้งค่าไว้ (โดยค่าเริ่มต้นคือ Anthropic)
- มอดทำงานแยกตามผู้ใช้และตามเครื่อง และผู้ใช้ปิดได้ทุกเมื่อ (`/pdpa-guard off` หรือ `claude plugin disable`) จึงบังคับใช้จากส่วนกลางไม่ได้ และมอดไม่เก็บบันทึกการตรวจสอบ (audit log) ว่าปกปิดอะไรหรือส่งอะไรออกไป จึงใช้แสดงว่ามีมาตรการควบคุมอยู่จริงไม่ได้

หมายเหตุเพิ่มเติมเฉพาะหน้านี้

- ชื่อและที่อยู่จะถูกตรวจพบเฉพาะเมื่อตามหลังป้ายกำกับที่กำหนด เช่น `ชื่อ` `นามสกุล` `full name` `first name` `ที่อยู่` `home address` หรือสำหรับชื่อ เมื่อตามหลังคำนำหน้า เช่น `นาย` `นาง` `Mr` `Dr` ส่วนป้ายกำกับภาษาอังกฤษ `name:` หรือ `address:` ที่ไม่มีคำขยายจะไม่ถูกตรวจ
- บล็อกรูปภาพหรือเอกสารไม่ถูกตรวจ แต่ข้อความที่เครื่องมือส่งกลับมาเป็นผลลัพธ์ของเครื่องมือ เช่น ผลลัพธ์ของคำสั่งที่แสดงข้อความในไฟล์ จะถูกตรวจ
- พรอมต์ระบบยังรวมข้อมูลสภาพแวดล้อม เช่น เส้นทางของโฟลเดอร์ที่ใช้ทำงาน และส่วน `memory` ของพรอมต์ระบบ ส่วน `CLAUDE.md` ไม่ได้อยู่ในพรอมต์ระบบ แต่ถูกส่งเป็น context block และถูกปกปิด
- ไม่ควรพึ่ง pdpa-thai เพื่อกันค่าเดิมไม่ให้ไปถึง Remote Control หรือไคลเอนต์ SDK ที่เซสชันส่งสตรีมไปให้

## แนวทางด้าน AI จากหน่วยงานไทย

- **เว็บไซต์ PDPC มีร่างแนวปฏิบัติเกี่ยวกับ AI** ซึ่งเปิดรับฟังความคิดเห็นระหว่างวันที่ 19–25 กุมภาพันธ์ 2569 ([หน้าประกาศ](https://www.pdpc.or.th/22291/)) ณ วันที่ตรวจสอบ (4 ตุลาคม 2569) เอกสารดังกล่าว**ยังเป็นร่าง** และ**ยังไม่ได้ตรวจสอบเนื้อหา** โปรดตรวจสถานะล่าสุดจาก PDPC
- **ETDA และ MDES** เผยแพร่คู่มือด้านธรรมาภิบาลการใช้ generative AI ([หน้าข่าว ETDA](https://www.etda.or.th/th/pr-news/AI_Gov_Anual.aspx)) เอกสารนี้ตรวจสอบเฉพาะชื่อเรื่อง

## เช็กลิสต์สำหรับนักพัฒนา

- [ ] **ลดข้อมูลตั้งแต่ต้นทาง** ให้ Claude อ่านเฉพาะสิ่งที่จำเป็นต่องาน ไม่ส่งไฟล์ส่งออกจากฐานข้อมูลหรือ log ทั้งไฟล์ ให้เลือกเฉพาะคอลัมน์หรือบรรทัดที่ต้องใช้
- [ ] **ใช้ข้อมูลทดสอบสังเคราะห์ (synthetic test data)** แทนข้อมูลลูกค้าจริงใน fixture และ seed
- [ ] **ตรวจพรอมต์ก่อนส่ง** โดยเฉพาะข้อความที่คัดลอกมาจากแชตลูกค้า ทิกเก็ตแจ้งปัญหา หรือระบบหลังบ้าน
- [ ] **เก็บข้อมูลลับ (secrets) เช่น รหัสผ่านและ API key ไว้ในตัวแปรสภาพแวดล้อม (environment variables)** หรือระบบจัดการข้อมูลลับ ไม่เขียนลงในโค้ดหรือ `CLAUDE.md`
- [ ] **ไม่ใส่ข้อมูลส่วนบุคคลใน `CLAUDE.md`** และไฟล์ context อื่นที่ถูกส่งทุกรอบ
- [ ] **ตั้งค่าสิทธิ์ (permissions) ของ Claude Code** เพื่อปฏิเสธการเข้าถึงไฟล์หรือโฟลเดอร์ที่มีข้อมูลจริง และตรวจจากเอกสารของ Claude Code ว่ากฎเหล่านั้นครอบคลุมอะไรบ้าง
- [ ] **ปกปิดข้อมูลส่วนบุคคลใน log ของแอปพลิเคชัน** ตั้งแต่ตอนบันทึก
- [ ] **เปิด pdpa-thai ในโหมด `redact` หรือ `block`** และเข้าใจข้อจำกัดใน [DETECTION.md](DETECTION.md)
- [ ] **ก่อนบันทึกหรือแชร์หน้าจอ** สั่ง `/pdpa-blur record` ระวังไม่ให้มีข้อมูลส่วนบุคคลในช่องพรอมต์ หน้าต่างอื่น และผลลัพธ์ของเครื่องมือหรือคำสั่ง และตรวจวิดีโอที่บันทึกไว้ก่อนแชร์
- [ ] **ตรวจนโยบายขององค์กร** ว่าอนุญาตให้ใช้เครื่องมือ AI ใด กับข้อมูลประเภทใด และองค์กรมีข้อตกลงกับผู้ให้บริการหรือไม่
- [ ] **ตรวจสัญญากับลูกค้า** หากทีมประมวลผลข้อมูลแทนลูกค้า
- [ ] **ขอคำปรึกษา** จาก DPO หรือทนายความ และสอบถามการตีความอย่างเป็นทางการจาก PDPC
- [ ] **รู้ขั้นตอนเมื่อเกิดเหตุ** หากข้อมูลส่วนบุคคลถูกส่งออกไปโดยไม่ตั้งใจ ให้แจ้งตามกระบวนการรับมือเหตุละเมิดขององค์กร

## สิ่งที่ยังไม่ได้ตรวจสอบ

- **ราชกิจจานุเบกษา** เว็บไซต์ปฏิเสธการเข้าถึงแบบอัตโนมัติ ตัวบทที่ใช้จึงเป็นฉบับ PDF ที่เผยแพร่บนเว็บไซต์ PDPC และยังไม่ได้เทียบกับฉบับในราชกิจจานุเบกษา
- **เนื้อหาของร่างแนวปฏิบัติเกี่ยวกับ AI บนเว็บไซต์ PDPC** ยังไม่ได้ตรวจ ร่างอาจเปลี่ยนแปลงก่อนประกาศใช้
- **คู่มือของ ETDA/MDES** ตรวจเฉพาะชื่อเรื่อง ไม่ได้ตรวจเนื้อหา
- **หน้าการแจ้งเหตุละเมิดของ PDPC** อ่านเฉพาะชื่อเรื่อง เงื่อนไขและระยะเวลาการแจ้งจึงไม่อยู่ในเอกสารนี้
- **การใช้บริการ AI บนคลาวด์เป็นการโอนข้อมูลไปต่างประเทศหรือไม่** ไม่ได้สรุป เพราะขึ้นอยู่กับข้อเท็จจริง
- **บทลงโทษ ค่าปรับ และกำหนดเวลา** ไม่อยู่ในขอบเขตของเอกสารนี้โดยเจตนา
- **การจัดการข้อมูลของผู้ให้บริการโมเดล** (Anthropic หรือแพลตฟอร์มคลาวด์ที่ตั้งค่าให้ Claude Code ใช้) เช่น สถานที่ประมวลผล ระยะเวลาเก็บรักษา และการนำไปใช้ ไม่อยู่ในเอกสารนี้ โปรดตรวจข้อกำหนดของผู้ให้บริการและข้อตกลงขององค์กร

หากพบข้อความที่ไม่ถูกต้องหรือแหล่งข้อมูลที่ล้าสมัย โปรดแจ้งผ่าน [GitHub Issues](https://github.com/Boom-Vitt/boombignose-mods/issues)
